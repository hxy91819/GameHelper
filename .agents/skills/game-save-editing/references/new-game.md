# 新游戏分析与适配

## 可通用到什么程度

| 层级 | 可复用部分 | 仍需适配的部分 |
| --- | --- | --- |
| 文件操作 | 候选盘点、哈希、备份、并发变化检查、替换与回退 | 存档目录、槽位及多文件关系 |
| 容器与编码 | JSON/XML/SQLite、Base64、压缩、常见加解密组件 | 变换顺序、密钥派生、盐/IV、校验和 |
| 游戏语义 | 显示原值、限制变化集合、数值范围校验 | 金钱字段、类型、关联字段与版本迁移 |

因此适合“通用操作流程 + 已验证的游戏适配资料”，无法仅凭游戏引擎或一个显示数值自动适配所有游戏。后续确需产品化时，再提取已重复使用的组件；当前 skill 不新增 GameHelper 运行时能力。

## 分析路径

1. 从安装目录的引擎标志、配置和运行日志确认身份，缩小存档搜索范围。Unity 可读 `*_Data/app.info` 取得公司名和产品名；`persistentDataPath` 常见于 `%USERPROFILE%/AppData/LocalLow/<公司>/<产品>`，这是候选规则而非已确认路径。
2. 查看头部、大小和编码。Base64 是编码；解码后高熵数据可能是压缩或加密，不能直接认定 AES。先查现有读写函数与依赖。
3. Unity Mono 可分析托管程序集；IL2CPP 常见 `GameAssembly.dll` 和 `il2cpp_data/Metadata/global-metadata.dat`。Il2CppDumper 能给出类型、字段和方法地址，实际算法仍需结合原生反汇编确认。Unity 序列化资产也可能包含密码等配置。
4. 以调用参数与数据布局验证算法，先解出完整结构并检验 padding、编码及记录关系。避免无限猜密码；已知资料无匹配时回到读写路径。二进制反编译地址和常量都绑定具体版本。
5. 没有代码线索时，可对可回退的副本做一次受控游戏操作，比较操作前后数据。显示整数可能对应 float、缩放值或多个字段；单次搜索命中不构成字段确认。

## MSIX 路径视图陷阱

本次案例中，从 Codex 执行的 `C:/Users/<user>/AppData/LocalLow/...` 与显式 `AppData/Local/Packages/<CodexPackage>/LocalCache/LocalLow/...` 返回相同旧文件，但普通启动游戏的实际目录缺少进度文件。

在当时具备本机管理共享权限的环境中，`\\localhost\C$\Users\<user>\AppData\LocalLow\...` 提供了不同的实际文件视图。`\\?\C:\...` 在该环境仍返回旧视图，不能视为可靠绕过手段。管理共享不可用时，使用应用外启动的文件管理器/终端等独立视图验证，不为此启用共享或修改系统权限。副本相同不是误差原因已被排除的证据。

## 验证记录模板

- 游戏名称、版本/Build、引擎与必要文件指纹。
- 候选与实际路径、启动方式、定位证据。
- 解码步骤、算法参数及其代码/资产来源。
- 字段路径、类型、原值和目标值；与用户观察的差异。
- 备份位置、修改前后哈希、结构差异集合。
- 文件回读结果；游戏内验证结果或明确待验证。
