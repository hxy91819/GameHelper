# Desktop 侧数据存储

ADR-0004 批次 5 将手帐、手动类型覆盖、海报关联、完整草稿、扫描选择和主题切换到 `userdata.db`。图片本体、Steam 元数据和 YAML 仍沿原路径。scope 为规范化绝对配置路径，比较沿用 `GH_ORDINAL_IGNORE_CASE`；同一 DataKey 的历史跨配置共享，六类侧数据互相隔离。

## 激活与补导入

后台初始化在报告存储就绪前、Desktop 在创建视图前，通过共享初始化器检查 schema 与激活记录，并调用 `ImportScopeAsync`。Desktop 在工作线程完成初始化／补导入。仅处理当前配置，不枚举磁盘；备份、严格解码、原件哈希复核在事务前完成，六类数据和 scope 完成事实同事务提交，已有 scope 不再重导。共享历史不进入该事务，也不创建新候选库。整份损坏或无法无损表达的文档阻断导入，原件和备份保留。

不存在已激活库时继续读写旧 JSON。已激活库读取、版本或写入故障明确报错，不回落为另一份可写 JSON 权威。Desktop 视图不接触 SQL／连接，`DesktopDocument<T>` 只持有 Infrastructure 返回的文档快照与不透明版本。

## 保存与冲突

冻结 JSON DTO 是适配边界，数据实际位于关系表；SQL 只在 Infrastructure。导入不额外 Normalize 类型，正常保存沿用现有 Normalize，父行存在且子项为空仍表示显式“未分类”。草稿所有字段（Baseline、启动选项、动作、倍速热键及不完整输入）按原 payload 保存，不作为运行配置读取。

手帐、类型和关联只提交本次修改的 DataKey。不同进程写不同项可同时成功；同一项期望版本过期则整体回滚。版本记录含删除墓碑，重新读取不存在的项仍带最后删除版本，允许明确重载后重新添加，同时拒绝旧窗口的 ABA 覆盖。更新原项保留 position。草稿集合、扫描选择和主题按集合版本冲突，不悄悄覆盖另一窗口；草稿原有 ID 保留，新项 UUID；扫描目录顺序和六项上限、忽略路径顺序保持原语义。

手帐、类型、关联和主题均在保存成功后更新内存值。保存失败显示错误并保留编辑；手帐重新打开会重读最新基线。草稿串行后台保存，失败不推进去重基线，UI 输入保留；保存 YAML 前等待草稿成功落库，成功后再清除草稿。关闭窗口异步等待待写草稿，失败保持窗口与编辑；现有“重新加载”丢弃修改入口接受最新集合基线。SQLite 的错误转换为现有界面可处理的保存错误。只读扫描视图仍保留内存行为。

## 写事务与后台事件预算

网络、界面编辑、JSON 解码与草稿序列化在取得写锁前完成。每次写操作单独连接，采用和会话事件相同的单调五秒争用预算，且在工作线程等待；不在 UI 线程调用同步数据库等待。取得写锁后，Desktop 增量写／scope 导入采用 250 ms 协作式执行预算，在逐项写和提交前检查，超出回滚；不在写事务内投影、网络请求或通知。

一个正常按预算执行的 Desktop writer 给后台增加约最多 250 ms 的写锁占用及提交／回滚开销；Desktop 自己等待写锁的时间并不占有 writer，也不会加到后台的五秒预算。连续竞争、线程调度或底层磁盘停顿不具备硬实时上限，因此不承诺所有停止事件都能当场提交。后台始终沿用同一事件五秒争用上限；耗尽时按批次 3 保留原固定终点待补录，不叠加第二轮五秒。测试以事件屏障保证 Desktop 持有真实写事务时后台开始停止写，验证释放后在原事件预算内完成。

## 报告与兼容窗口

报告读取的历史修订、历史与当前 scope 手帐来自同一短读事务。释放连接后 Core 计算通关条目、排序与前期数量；IPC 返回 `JournalIncluded` 标志，Desktop 只对旧文件后端执行旧合并。手帐短评仍只展示／手动导出，不进入 sync 或模型请求；本批不启用评分。

库提交同事务标记对应兼容目标 dirty。Desktop 合并重复投影请求，在后台通过数据目录协调锁输出全部已导入 scope 的六类 JSON；后台启动与停止也排空完整投影。投影失败保留 dirty/failure，不撤销库成功提交，不导致编辑重复落库；准备降级仍须离线重试并校验所有目标。Desktop 正常关闭等待已请求的投影工作结束。兼容窗口和降级协议沿用 ADR-0004。

## 验证

`SqliteDesktopDataTests` 使用临时真实 WAL 库，覆盖 scope、历史不重导、Unicode 比较、不同项合并、同项及删除重建冲突、草稿全字段与 ID、空类型、扫描排序上限、完整兼容 JSON、报告读事务与后台停止写争用。`SqliteDesktopUiTests` 覆盖保存冲突编辑不丢、失败不推进草稿去重与真实 store 路径。时间来自注入时钟，竞争用事件屏障协调。

`sqlite-publish-smoke.ps1` 在两种 Windows 发布布局启动两个真实子进程，两者先读取同一基线再同时保存：不同 DataKey 均成功且都保留，同 DataKey 恰有一个冲突；驱动只添加测试程序，SQLite 依赖仍来自正式发布产物。
