# WPF 游戏库

日常打开桌面的 **GameHelper 游戏库**，或运行正式发布目录下的 `desktop\GameHelper.Desktop.exe`。窗口连接现有监控实例，没有实例时在后台启动同一发布目录下的运行时。开机只启动后台监控，关闭游戏库继续监控；自动更新恢复游戏库时不激活窗口。

## 外观主题

侧栏底部的“浅色主题 / 深色主题”按钮切换整个游戏库的外观，立即生效，无需重启监控。游玩档案的图表、日历、表格和导入／海报匹配弹窗使用同一配色；海报和应用图标保持原色。切换不改变当前分组、布局、搜索和未保存草稿。

初次使用沿用深色；选定后，下次打开游戏库和部署恢复窗口会记住选择。偏好按配置路径单独保存在 `config.yml.desktop-theme.json`，不写入运行时 `config.yml` 或草稿文件。文件缺失、损坏或主题名称未知时回退深色。若数据目录不可写，提示保存失败并保持原主题。后台入口和一次性 CLI 不修改主题偏好。

界面按 A / Studio 原型还原：210px 类型侧栏、76px 顶栏、横版大图继续游戏区、四列 2:3 竖版海报与 252px 详情卡；浅色与深色保持同一布局。侧栏以书架、柱状图、调节器分别表示游戏库、游玩档案、游戏管理，统一线宽与圆角；顶栏使用主页图标。海报下方只显示累计时长，安装状态继续在海报角标、详情及筛选中展示。海报尺寸随列宽调整，鼠标停在海报上也可用滚轮滚动整页。右侧详情与本周摘要随页面滚动吸顶，保留 16px 顶部间距；窗口高度不足时右侧单独滚动，到达边界后继续滚动整页。具体尺寸、字体和品牌来源见[视觉契约](../architecture/studio-visual-contract.md)。首页“继续旅程”来自真实最近游玩或正在运行且已安装的游戏，点击沿用保存后启动流程；运行中的游戏只定位详情。

## 全局设置

侧栏“全局设置”集中配置开机自启、ETW / WMI 监控方式、按显示器 HDR 允许勾选、休息提醒、DDC 自动预设、Cheat Engine 路径及 GitHub 同步。与游戏设置分开保存；切换页面保留本次窗口内的草稿，“放弃草稿并重新载入”读取后台的最新配置。

文件校验会收集各段错误；游戏诊断使用 `Game 'x'` 标识，并保留对非法 `speedAttach` 和无法解析的 `addedAt` 的加强检测。

保存前由 Core 的 `AppConfigValidator.ValidateGlobals` 检查全局设置（不校验无关的游戏启动配置），失败不写配置，也不应用开机启动和运行时重载。保存成功后注册／取消开机启动并重载游戏自动化；监控方式需重启后台才生效。休息提醒时长必须为正整数；CE 路径可留空，填写时需为 Windows 绝对 `.exe` 路径。若系统注册或运行时重载失败，明确提示“已保存”与未应用的原因，避免误判为未保存。

HDR 勾选列出活跃显示器，不改变当前 Windows HDR 状态；未连接显示器的规则保留。查询失败时继续保留已保存规则。自动 HDR 仍需游戏自身开启 HDR；当前显示器被排除时沿用 DDC 降级策略。

DDC 向导在关闭自动预设并保存、所有显示器 HDR 关闭时使用：先读取舒适模式，再手动切到游戏模式读取，生成两个方向的差分配方，确认后进入全局设置草稿；最终点击“保存全局设置”才生效。详见[显示器预设录制](monitor-mode.md#ddc-两步录制向导)。

GitHub 区域支持 git / api、仓库、分支、子目录、间隔、CSV 和 Token。Token 用掩码输入，留空可使用 `GAMEHELPER_GITHUB_TOKEN`；git 方式复用本机凭据。“测试连接”只验证连接，“立即推送”强制触发一次现有同步服务；两者都使用已保存配置，状态展示最近成功时间及错误。

选中海报使用边界内的同心双层描边，四角完整；正在运行的游戏（含外部启动）显示绿色呼吸光环，网格与列表均保留，游戏退出后停止动画。两种主题使用同一组主题色资源。

详情的“编辑私人手帐…”可保存归档状态、可选通关日期和单行 80 字短评，与[游玩档案](playtime-dashboard.md#私人手帐原型-a)共用本机侧存储，不修改启动配置，也不随 sync 上传。

## 游戏类型

侧栏按实际类型显示动态数量，一款游戏可以归入多个类型。类型过滤与安装状态、搜索、HDR / 倍速能力筛选叠加；返回“游戏库”清除类型筛选。没有类型的条目显示“未分类”，切换不丢失启动设置草稿。

自动类型只复用明确 Steam 启动入口、安装身份或已确认的海报 AppID，不按模糊名称推测。桌面端异步读取商店 `appdetails` 的 `genres`（中文），不把 `categories` 中的单人、合作、成就等功能当成类型。该端点是尽力可用的商店接口，不保证稳定可用；加载游戏库与后台监控不等待网络。

- 元数据保存在数据目录的 `cache/steam-genres/<AppID>.json`，成功结果缓存 30 天；失败至少间隔 6 小时再尝试，保留上次成功类型。请求串行、最少间隔 1 秒，超时 12 秒，响应上限 256 KiB；没有缓存时降级到未分类。
- 详情的“编辑游戏类型…”可输入逗号分隔的多个类型；保存为空明确设为未分类。“恢复 Steam 自动类型”删除手动覆盖。手动结果写入配置旁 `config.yml.desktop-genres.json`，自动更新不会覆盖，且不改监控配置、启动入口或历史。
- 只读截图复用本地关联和缓存，不请求网络、不写类型。缓存过期时会在下次创建游戏条目、重新载入或重新关联海报时检查更新；不会随每次状态轮询重复抓取。

## 使用

- 网格 / 列表切换、名称或程序搜索，`Ctrl+F` 聚焦，`Esc` 清空。显示已结算的历史时长，不把待启动时间记作游玩时间。运行中的游戏会实时显示本局已玩时间（见[运行中计时与休眠暂停](#运行中计时与休眠暂停)）。
- 详情卡直接提供 HDR、手柄和倍速开关；名称、程序路径、参数、自动化开关、海报和类型编辑在“设置与管理…”二级面板。选中游戏后可编辑名称、HDR、倍速和启动入口；“保存设置”原子保存并热更新配置。“启动游戏”会先保存当前游戏的修改。双击海报执行同一启动命令及禁用条件，请求成功后最小化游戏库并把前台让给游戏；启动失败时保持窗口并照常显示错误。
- 主倍速在“设置与管理…”面板用滑块选择，区间 0.1–10×、步进 0.1，旁边即时显示当前倍率。勾选“游戏倍速”后拖动滑块即写回草稿。游戏内热键仍按各行的“档位=倍率”格式填写，可配置超出滑块区间的档位。
- 启动入口可为完整 exe、`.lnk` / `.url` 快捷方式路径，或 `steam://rungameid/数字`。参数和工作目录在展开区设置；Steam URI 不附带这两项。仅有进程文件名的旧配置需要补全启动入口；旧绝对 exe 路径默认可启动。
- 使用 Mod、平台启动器的游戏，选择原本使用的快捷方式。用于识别的程序仍填写实际游戏进程，两者可以不同。
- 顶部“添加游戏”或侧栏“游戏管理”打开程序添加、目录扫描和 Steam 扫描菜单；“扫描 Steam”读取本地游戏库，确认选中条目后导入。新条目使用 Steam 平台入口，重复导入保留已有条目的全部设置。
- 添加／管理菜单内的“扫描目录”选择本地游戏库或单个游戏目录，先只读扫描，再勾选批量添加。默认不勾选，按游戏目录分组显示名称、完整路径与推荐依据。每个目录最多选择一个程序，选择备选时会替换同目录旧选择；“只选推荐程序”仅选择当前搜索结果中的推荐项，已在库的程序不可重复勾选。疑似运行库、卸载器、崩溃上报器、CRC 校验及 Workshop 工具默认收起，可勾选“显示辅助程序”手动查看；再次收起时会取消这些辅助项的选择。搜索不会丢失其他已选游戏，底部按钮显示总选择数。新游戏的 HDR 和倍速默认关闭，已有条目完整保留；不执行候选程序，也不持续监视目录。
- 扫描过的目录会记入添加／管理菜单的“重新扫描 <目录>”（最近 6 个），一键重扫；目录已不存在时从列表移除。每次重扫都会完整遍历目录，不跳过上次扫过的位置，以免漏掉新装的游戏。
- 结果默认只展示新游戏目录：已有程序在游戏库的目录、以及点过“忽略此目录”的目录默认收起，可分别勾选“显示已在游戏库的目录”“显示已忽略的目录”查看；在显示已忽略时点“取消忽略”恢复。忽略按目录内所有候选程序记录，之后该目录新出现的程序会作为新候选重新出现。最近目录和忽略列表保存在配置旁 `config.yml.desktop-scan.json`，不修改 `config.yml`；保存失败只提示，不影响扫描。
- 首次打开、返回“游戏库”及切换游戏类型时，默认只看“本机已安装”，隐藏本地未找到的游戏海报；手动切换仍可查看其他安装分组。其他分组为“本地未找到”“待确认”和“全部”。已知完整程序路径缺失才归入未找到；仅有程序名、无法确认的平台入口或访问错误归入待确认。Steam 本地清单可补充确认旧的程序名条目。切换分组不删除配置、草稿或历史，历史统计始终包含已卸载游戏。
- “从目录移除”需要确认，历史记录保留。关闭自动化后仍可普通启动，但不应用 HDR、倍速或计时。
- 海报优先使用工具缓存和 Steam 客户端本地缓存，缺少时从 Steam 官方站点自动下载。下载在后台执行，不阻塞游戏启动。

## 库内启动与外部启动

**库内启动**会在拉起进程前确认 HDR；进程被识别后进入`运行中`状态，按设置应用倍速和配套软件。HDR 游戏运行期间显示器预设让位。

**外部启动**（Steam"开始"按钮、桌面快捷方式、其他启动器）照常计时、应用倍速，并按手柄支持设置启动／复用或关闭 DS4Windows；库中显示`运行中·外部`，一样显示本局计时并优先排列。外部启动不切换 HDR，即使勾选了 HDR，也降级为显示器游戏模式（遵循 monitorMode 开关与日照规则）。已运行游戏不允许再次启动或运行中补切 HDR；需要前置 HDR 时请退出后从游戏库启动。监控启动时补扫到的进程也遵循外部启动规则；恢复快照保留原有启动来源。

跨重启的在途会话按快照里的启动来源恢复 HDR 资格，倍速和配套软件不受来源限制；升级前的旧快照没有标记时保留历史连续性口径。监控器启动时补扫到的游戏保持外部来源，不补切 HDR。休息提醒只看前台窗口是否为配置内游戏，与启动来源无关。

显示器预设（monitorMode）与 HDR 自动化互斥：库内启动且勾选了"启动前开启 HDR"的游戏在跑时，预设自动切换整体暂停；外部启动不因 HDR 勾选而暂停。无论启动来源，系统 HDR 已开启或状态无法确认时仍不做 DDC 读档或写档，确认 SDR 后恢复（见[显示器预设](monitor-mode.md#与-hdr-自动化的关系)）。

## Steam 海报

明确的 Steam App ID 来自已确认的海报关联、Steam 启动 URI / `.url`、本地 `appmanifest_*.acf` 或附近的 `steam_appid.txt`。安装清单优先于旁边的 ID 文件；名称搜索的自动关联使用下述置信度规则。

选中游戏后点击“匹配 / 重试 Steam 海报”，使用中文或英文名称搜索并选择对应版本，或填写 Steam 商店链接 / App ID。选择立即保存，可重试下载；“恢复自动识别”清除手动关联。搜索只发送输入的名称，不发送本地程序路径。无需 Steam 登录或 Web API Key。

“按名称补全海报”集中显示缺少封面的本机游戏，也可包括其他安装分组。选择游戏即可搜索，默认勾选“搜索后自动采用最佳匹配”，可关闭此选项只预览；“批量采用最佳匹配”处理当前范围内未关联的游戏。搜索合并中英文结果，并通过 Steam StoreBrowse 获取英文别名及游戏类型，例如 Astral Ascent 可关联中文“星界战士”。已确认的 DLC、画集、原声带等附属内容不参与自动选择。

自动选择要求名称相似度至少 90%，领先第二名至少 10 个百分点；忽略标点、空格、商标和快捷方式后缀，罗马与阿拉伯序号可对应。仅已确认的本体允许小幅拼写差异，序号、版本关键词不同或多个相近结果都保留人工选择；类型元数据不可用时只接受唯一规范化同名。调整搜索词不改变用于自动判断的游戏名称。已有海报关联不会自动覆盖，手动“使用选中的海报”仍可替换。关闭窗口取消剩余工作，已完成关联保留；网络失败可重试。

目录扫描最多读取 10,000 个目录、50,000 个条目、8 层子目录、1,000 个候选程序或约 25 秒，达到任一上限会明确提示缩小目录重扫。不跟随目录链接；不可读目录计数提示。扫描保留辅助程序候选但不推荐它们，跳过同名 exe 对应的 Unity _Data 资源目录以节省预算。推荐依次使用同名 Unity _Data 与引擎文件、同名 Godot .pck、Unreal Binaries 下的 Shipping、Ren’Py 资源结构、程序／产品名与游戏目录匹配等证据；大小只用于同分排序，不建立推荐。同目录多个候选证据相当或没有明确特征时标为待确认，不推荐。扫描单个游戏目录时，会结合根目录 exe 与引擎／Binaries 结构将启动器和深层程序归为同组。它不保证所有 exe 都是游戏，导入前应确认。导入时重新检查路径，已消失的候选会拒绝整批变更。已知文件的存在状态在刷新时重查，Steam 安装清单最多缓存 30 秒。

官方竖版图形规格见 [Steamworks Library Assets](https://partner.steamgames.com/doc/store/assets/libraryassets)。客户端读取公开的 StoreBrowse 图形元数据，支持带版本哈希的图片路径，并以传统 library capsule 地址兜底。公开服务格式和资源可用性可能变化，获取失败时使用已有缓存或图标，不影响监控、计时和启动。

下载限制为两笔并发、每个 App ID 一次共享请求，单笔海报最大 5 MiB；解码验证后原子写入 `%AppData%\GameHelper\cache\steam-posters\<AppID>.jpg`。相同窗口不会在状态轮询时重复下载。失败标记退避五分钟；重新打开后可自动再试，手动匹配 / 重试可立即重试。已有有效缓存离线仍可使用。

手动关联单独保存在配置旁 `config.yml.desktop-artwork.json`，更新或关闭后保留，不修改 `config.yml`、启动入口或 HDR / 倍速设置。后台开机模式不创建游戏库，也不下载海报。

## 最近活动与刷新

各安装分组内优先显示正在运行的游戏，其后按最近一次已结束的游玩时间与添加时间的较新值排序。同一活动时间优先最近游玩；没有日期的旧条目按配置列表顺序倒序稳定兜底，不将其视为真实添加时间。新游戏通过添加、Steam 或目录导入时记录可选 `addedAt`（ISO 8601，含时区），重复导入及编辑保留原值；旧条目不补造日期。最近游玩取有效历史会话的结束时间，未来或无效记录不参与排序。

后台状态轮询不禁用菜单，保留没有变化的列表项、选择、草稿和海报；只有实际变化才调整对应条目。保存等主动操作仍显示忙状态，操作前发出的旧轮询响应不会覆盖其结果。海报对话框的列表在搜索、禁用与重新启用时保持深色背景。

## 运行中计时与休眠暂停

运行中的游戏海报显示连续旋转的渐变流光描边与柔和呼吸光晕，与选中框保持同心；退出运行态时停止动画并隐藏光环。

运行中的游戏在卡片徽章、列表状态列和右侧详情显示"运行中 · 00:12:34"，卡片下方另有绿色"本次已玩"一行，逐秒推进；游戏退出或该会话结束后恢复普通状态文本。计时来源是监控进程的本局会话开始时间：界面轮询到一次后用本地时钟自行推进，秒级刷新不产生后台通信。

系统进入睡眠或休眠时计时暂停：唤醒后监控把整段休眠时长从活跃会话的开始时间中剔除，休眠时间不计入游玩时长，会话本身跨休眠保留（结合[in-flight 快照恢复](etw-recovery.md)），落盘时"开始时间"为剔除休眠后的有效开始时间，保持时长等于起止差。监控进程未运行时没有计时，也没有休眠剔除问题。

## 启动前 / 退出后通用动作

在游戏详情的动作区添加程序动作，可编辑时机、运行／关闭、exe 完整路径、参数，并用上移／下移调整顺序。动作跟随游戏设置保存；未完成的编辑会作为桌面草稿保留。

`games[].actions` 是可选列表，省略时保持原有配置写回格式。每项必须指定 `when: beforeLaunch|afterExit`、`type: run|close` 和 Windows exe 完整路径 `path`；`arguments` 可选，只用于运行；非法时机、类型或相对路径会在读写及校验时拒绝。`run` 的 `wait` 默认为 false；设为 true 时最多等待该程序退出 30 秒，非零退出码或超时视为失败。超时只结束等待，不终止该程序。运行请求隐藏窗口、不分配控制台，每次都发起新进程。`close` 只关闭完整路径一致且属于当前 Windows 登录会话的进程，复用 DS4Windows 的关闭步骤：先正常关闭，等待 1.5 秒，再终止并最多等待 3 秒确认退出；没有匹配进程即成功。`close` 不配置 `wait`，参数不参与关闭匹配。沙盒实例只关闭沙盒目录内的进程。

启动前动作仅从游戏库启动时执行，按列表中该时机的顺序运行，之后应用 DS4Windows 预设，再启动游戏。任一失败会提示并中止后续动作与游戏启动，已由 GameHelper 开启的 HDR 按既有失败路径恢复。暂停该游戏自动化不影响库内启动前动作。外部启动及快照恢复不补跑启动前动作。

退出后动作在受监控游戏最后一个进程退出、会话结束后投递到后台单消费者队列，库内和外部启动均适用；按投递顺序串行执行，每个会话只投递一次，失败记警告并继续后面的动作。进程事件回调只负责投递，不等待动作程序。GameHelper 停止监控时不触发退出后动作；恢复仍存活的游戏会在其后实际退出时执行，停机期间已退出的恢复会话只补写时长，不补跑动作。退出动作执行不持有自动化状态锁或 companion 锁；每项在共享状态锁内校验投递时的 generation 并登记执行租约，再在锁外做进程 I/O。Stop 在同一边界使未开始的旧动作失效、关闭队列，并在所有锁外最多等待正在执行的消费者 5 秒；超时记警告继续清理，不强杀已进入的进程操作。再次 Start 的消费者等待旧消费者结束，避免跨重启并发执行；晚到结果不写入新生命周期。队列关闭与清空分别尽力执行，已完成的托管队列不保留待办引用。

```yaml
games:
  - dataKey: example
    executable: C:\Games\Example\game.exe
    actions:
      - when: beforeLaunch
        type: run
        path: C:\Tools\prepare.exe
        arguments: --game example
        wait: true
      - when: afterExit
        type: close
        path: C:\Tools\overlay.exe
```

启动前动作仍在调用 Launch 的线程上同步执行，并在整个 Launch 期间持有 companion 锁。每个等待运行最多 30 秒，每个匹配的关闭进程最多等待 1.5 + 3 秒；多个动作、DS4Windows 操作及 HDR／系统调用会累加，整个 Launch 没有统一超时。外部启动的进程回调仍可能在应用 DS4Windows 时等待这个锁；后台退出动作不占用它。5 秒只限制退出动作 drain，不是整个 Stop 的耗时上限。

DS4Windows 预设与通用动作并列展示，仍原样存储在 `launch.ds4WindowsPath`，不自动迁移为动作。两者同时配置时，通用启动前动作先执行；同一程序同时出现在两处也按各自语义执行。

## PS 手柄兼容：启动前运行 DS4Windows

在游戏详情的“启动前 / 退出后动作”区域勾选预设“DS4Windows（PS 手柄）”，路径预填为本机的 `D:\Program Files\DS4Windows\DS4Windows\DS4Windows.exe`，也可选择其他位置。按游戏独立保存，默认关闭；未勾选时会关闭已运行的 `DS4Windows.exe`。游戏库启动、受监控游戏的外部启动及在途恢复均会应用此设置，普通 exe、快捷方式和 Steam 入口均支持，与游戏自动化开关独立。

启动前先检查游戏与 DS4Windows 路径，之后依照既有 HDR 流程，勾选时先确保 DS4Windows 运行；未勾选则先尝试正常退出当前 Windows 登录会话中的所有 DS4Windows 进程，1.5 秒内未退出时终止该进程，并最多等待 3 秒确认退出，再发起游戏启动。关闭失败会提示并阻止此次库内启动；外部游戏已经运行时只记录警告，不中断计时和其他自动化。只复用完整路径一致的进程；新启动请求隐藏窗口并禁止分配控制台，最多等待 5 秒进入 GUI 空闲状态。程序不存在、启动失败或未能完成启动时会提示错误，不继续启动游戏，已开启的本工具 HDR 会按既有失败流程恢复。GUI 空闲不代表驱动、手柄连接或虚拟手柄已经就绪；这些仍由 DS4Windows 的配置决定。游戏退出或 GameHelper 重启不会关闭它。

YAML 对应 `games[].launch.ds4WindowsPath`，省略或在界面取消勾选，表示启动该游戏时关闭 DS4Windows（不是仅跳过启动）。沙盒测试仅允许关闭可确认位于沙盒目录内的 DS4Windows，避免影响用户实例。例如：

```yaml
launch:
  target: steam://rungameid/620
  ds4WindowsPath: C:\Tools\DS4Windows\DS4Windows.exe
```

## HDR 和启动失败

开启监控 → 按显示器策略准备 HDR → 原入口启动 → 等待游戏进程 → 真实计时和倍速。HDR 查询失败或允许显示器未能确认开启时不启动游戏。平台入口返回不等于游戏成功运行；两分钟内未识别到已登记进程会显示超时并释放 HDR。启动中的同一游戏不能重复发起。

全局 `hdr:` 段可排除桌面显示器，或仅允许电视：

```yaml
hdr:
  allowedDisplays: ["Living Room TV"] # 可选；[] 表示不限制白名单
  disabledDisplays: ["DELL U2720QM"] # 可选；排除优先于允许
```

列表项按完整显示器名称或 Windows 显示器设备路径匹配，忽略大小写和配置值两端空格，不支持子串或通配符。同名设备会一起匹配，需要区分时使用设备路径。当前在 YAML 中配置，显示器选择界面留待后续阶段。列表必须是非空名称/路径组成的列表，`[]` 合法，省略整个段或两个空列表保留原来的整机 HDR 行为。

仅连接被排除或未进入白名单的显示器时，勾选 `hdr: true` 的库内启动会记日志并跳过开启 HDR，不获得 HDR 租约，不阻止游戏启动。在确认系统 SDR 且没有 HDR 租约时，自动降级为普通游戏的 DDC 预设，仍遵循 `monitorMode.enabled` 与日照规则（夜间护眼）。接入允许且支持 HDR 的电视后正常开启电视 HDR，配置了规则时不会顺带开启被排除显示器。HDR 已由用户开启时沿用原有逻辑，不抢归属，也不允许 DDC 切档。

规则随配置热重载，无需重启；后续启动立即使用新规则。运行中的库内 HDR 游戏在下一次事件或约 10 秒检查时重新评估，接入允许的电视后可正常开启 HDR 并暂停 DDC。规则不是强制关闭开关，不会因排除一个显示器立即关闭其已有 HDR；若没有可用目标的原因是硬件不支持 HDR 或被 Windows 强制禁用，而非被规则排除，仍会阻止启动；无活跃显示器或查询失败也不会放行。

最后一个需要 HDR 的游戏及待启动请求结束后，仅恢复本工具原先开启的 HDR。用户原本已打开的 HDR 保持开启。归属与启动截止时间随会话快照跨程序重启保存，恢复时不重复启动游戏。HDR 已开启或状态未知期间不尝试 DDC 显示器预设切换。

从 Steam 等外部入口直接启动仍可被监控并自动应用倍速、显示器预设和配套软件，但不会切换 HDR。游戏需要前置 HDR 时应从游戏库启动。

## 游戏内倍速热键

游戏设置面板启用“游戏倍速”后，可在“游戏内倍速热键”中每行填写一项：`Ctrl+F1=2` 设置两倍速，`Ctrl+F2=1` 一键恢复原速，`Ctrl+F3=toggle` 在主倍速和原速之间切换。多个档位分别绑定快捷键；清空文本会移除所有倍速热键。支持 Ctrl/Alt/Shift 与 F1–F12、A–Z、0–9，倍率使用小数点。

保存时校验组合重复、键名与倍率；修改和未完成文本都随草稿保留，重新载入时放弃。外部修改热键也会触发保存冲突。配置保存后在下次游戏启动时生效；关闭倍速后 CE 不会附加，已保存热键不主动生效。详情见[游戏倍速配置](game-speed.md)。

## 保存、草稿与冲突

界面修改先成为草稿，不立即改写 `config.yml`。草稿单独保存在同目录 `config.yml.desktop-drafts.json`，包括尚未输入完成的倍率文本；关闭、崩溃或部署重启后继续编辑。“重新载入”确认后放弃草稿。不同配置的游戏库互不影响，同一配置只打开一个编辑窗口。

外部修改或 CLI 修改同一游戏后，旧草稿保存会报告冲突。重新载入最新设置再修改，避免覆盖其他入口的更新。通信超时不会自动重试保存或启动；刷新确认实际状态后决定下一步。

## 配置格式

```yaml
games:
  - dataKey: my-game
    executable: C:\Games\MyGame\game.exe
    displayName: My Game
    enabled: true
    hdr: true
    launch:
      target: C:\Games\MyGame\mod-loader.exe
      arguments: -windowed
      workingDirectory: C:\Games\MyGame
```

`launch` 可省略；绝对 `executable` 路径作为默认入口。它不改变 `dataKey`、进程匹配或历史记录身份。保存运行中的游戏设置时，倍速在下一次真实启动时应用。

## 开发与验证

先正常启动 ConsoleHost，再执行 `dotnet run --project GameHelper.Desktop`。自定义配置使用 `--config <完整路径>`。`GAMEHELPER_DATA_DIR` 仍按既有隔离规则追加 `GameHelper` 子目录。

发布 ConsoleHost 的 win-x64 产物会在 `desktop/` 一起发布 WPF；不能把另一种运行时布局逐文件覆盖进去。完整部署仍执行 `scripts/verify-on-machine.ps1`。脚本会一并原子换入两个入口，重启原本打开的游戏库，并通过实际 IPC 查询验证连接。

只读验收支持 `GameHelper.Desktop.exe --config <沙盒配置> --snapshot <输出目录>`：不激活地显示渲染窗口，连接指定隔离实例，输出网格、列表、空搜索和最小窗口截图后退出，不保存设置或启动游戏。`--check <输出JSON>` 执行无窗口的只读连接探针。

快照还输出 `installed-default.png`、`missing-games.png`、`unknown-games.png` 以核对安装分组，`launch-options.png` 展示滚动后的启动设置；后续布局截图会选择全部分组，以覆盖隔离测试中已不存在的示例路径。设置 `GAMEHELPER_TEST_SCAN_DIRECTORY` 可附加只读扫描与 `directory-scan.png`，不会导入候选。

快照模式仅用已有海报缓存，不联网。实际下载与渲染回归需显式设置 `GAMEHELPER_TEST_STEAM_POSTER=1`，测试通过隔离数据目录启动不激活的真实 WPF 窗口，再检查缓存和只读截图；默认测试用 HTTP 替身验证缓存、坏响应、限流、大小限制和取消，不依赖网络。

`--background` 无窗口连接或启动监控；可组合 `--check` 返回就绪信息和运行时 PID。`--restore` 恢复游戏库但不激活窗口。后台运行时的输出在配置旁 `config.yml.runtime.log`，超过 5 MiB 时下次启动轮转为 `.previous`。排错仍可手动从终端运行 ConsoleHost 命令。

外部启动的配套软件在游戏进程被识别后启动，不保证先于游戏初始化；原程序已运行则复用。配套软件失败记录运行时警告，不阻断计时、倍速和显示器预设。库内启动仍先启动配套软件再拉起游戏，失败时不启动游戏。

## 横图与次级操作

继续游戏区使用 Steam 商店 capsule 横图，详情卡使用 header 横图；二者以已确认 AppID 解析，分别缓存为 `cache/steam-posters/<AppID>.capsule.jpg` 和 `<AppID>.header.jpg`，不把竖版封面拉伸成横图。复用海报下载的 5 MiB 上限、2 路并发、超时与原子写入；失败保留可用缓存，手动“匹配 / 重试 Steam 海报”同时重试横图。header 不可用时使用 capsule，两者都没有时显示首字占位；只读截图仅用已有缓存。

侧栏游戏管理保留添加、扫描、批量补海报和设置入口。搜索旁的更多筛选保留“本地未找到”“待确认”和“倍速”；主行显示“全部”“已安装”和 HDR，所有筛选仍可叠加。网格按钮在网格／列表间切换。本周摘要的数字与“小时”单位分级显示，文字列按内容自动分配宽度，并与趋势图保留间距，避免多位数遮挡；按本地周一至周日汇总已完成历史，未来日期为零；打开窗口、返回库页或主动刷新时更新，不在后台高频读历史。

启动前保存失败（例如旧草稿与最新配置冲突）时，错误会显示在右侧启动按钮上方。“放弃此游戏草稿并重载”只放弃当前游戏的草稿、读取最新设置，其他游戏的未保存修改保留；错误未解决前不会绕过保存直接启动。

## 手柄操作

窗口打开后自动读取 Xbox、PS4（DS4）、PS5（DualSense），仅前台窗口响应，不需要启动全屏主机界面。方向十字键或左摇杆移动选中海报，网格上下按当前列数移动；A / × 启动所选游戏，沿用双击海报的保存与启动流程。B / ○ 关闭当前 WPF 弹窗或游戏设置，再返回库页或清空搜索；原生文件选择框仍使用键鼠。Start / Options 打开游戏设置，LB/RB 或 L1/R1 前后移动三行。设置编辑仍使用键鼠。

窗口失焦或最小化即停止 16ms 轮询、关闭手柄句柄并退出 SDL Gamepad 子系统，重新激活后再初始化；自己的前台 WPF 弹窗仍可接收返回。重新初始化后须先松开再按，按住确认键不会启动游戏。

方向长按 400ms 后每 90ms 重复；左摇杆死区约 49%，对角取主轴。确认、返回、菜单不连发。失焦、切换设备后须先松开按键，避免返回窗口意外启动游戏。

同时可见多个设备时只读取一个：首次优先原生 PlayStation，其次按 SDL 设备 ID；当前设备完全松开（摇杆回死区）持续至少 0.5 秒后，其他已连接设备的新按下可接管；有输入或松开不足 0.5 秒时忽略其他设备，防止虚拟设备延迟镜像重复导航。冷却期内按住到期不触发接管，须有新按下；接管仅执行新按键边沿，不重放之前按住的确认键；不支持多人同时操控或自动识别虚拟设备背后的型号，不改 DS4Windows/HidHide 配置。设备类型通过桌面输入层暴露，虚拟 Xbox 按 Xbox 类型返回。

输入依赖 SDL3-CS 与 SDL3-CS.Windows 3.4.18.1（zlib），原生 SDL3.dll 随 NuGet runtime assets 发布；framework-dependent 与 self-contained 均需保留原生文件。初始化前以 Override 优先级强制禁用 enhanced reports（覆盖继承的环境变量）；若设置失败则停止初始化并在窗口显示错误，避免切换蓝牙 PS 手柄的报告模式，不启用震动。USB/蓝牙、热插拔与输入转换软件共存仍需 Windows 真机验收。
