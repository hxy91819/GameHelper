# WPF 游戏库

日常打开桌面的 **GameHelper 游戏库**，或运行正式发布目录下的 `desktop\GameHelper.Desktop.exe`。窗口连接现有监控实例，没有实例时在后台启动同一发布目录下的运行时。开机只启动后台监控，关闭游戏库继续监控；自动更新恢复游戏库时不激活窗口。

## 外观主题

侧栏底部的“浅色主题 / 深色主题”按钮切换整个游戏库的外观，立即生效，无需重启监控。游玩档案的图表、日历、表格和导入／海报匹配弹窗使用同一配色；海报和应用图标保持原色。切换不改变当前分组、布局、搜索和未保存草稿。

初次使用沿用深色；选定后，下次打开游戏库和部署恢复窗口会记住选择。偏好按配置路径单独保存在 `config.yml.desktop-theme.json`，不写入运行时 `config.yml` 或草稿文件。文件缺失、损坏或主题名称未知时回退深色。若数据目录不可写，提示保存失败并保持原主题。后台入口和一次性 CLI 不修改主题偏好。

界面按 A / Studio 原型还原：210px 类型侧栏、76px 顶栏、横版大图继续游戏区、四列 2:3 竖版海报与 252px 详情卡；浅色与深色保持同一布局。海报尺寸随列宽调整，鼠标停在海报上也可用滚轮滚动整页。具体尺寸、字体和品牌来源见[视觉契约](../architecture/studio-visual-contract.md)。首页“继续旅程”来自真实最近游玩或正在运行且已安装的游戏，点击沿用保存后启动流程；运行中的游戏只定位详情。

## 游戏类型

侧栏按实际类型显示动态数量，一款游戏可以归入多个类型。类型过滤与安装状态、搜索、HDR / 倍速能力筛选叠加；返回“游戏库”清除类型筛选。没有类型的条目显示“未分类”，切换不丢失启动设置草稿。

自动类型只复用明确 Steam 启动入口、安装身份或已确认的海报 AppID，不按模糊名称推测。桌面端异步读取商店 `appdetails` 的 `genres`（中文），不把 `categories` 中的单人、合作、成就等功能当成类型。该端点是尽力可用的商店接口，不保证稳定可用；加载游戏库与后台监控不等待网络。

- 元数据保存在数据目录的 `cache/steam-genres/<AppID>.json`，成功结果缓存 30 天；失败至少间隔 6 小时再尝试，保留上次成功类型。请求串行、最少间隔 1 秒，超时 12 秒，响应上限 256 KiB；没有缓存时降级到未分类。
- 详情的“编辑游戏类型…”可输入逗号分隔的多个类型；保存为空明确设为未分类。“恢复 Steam 自动类型”删除手动覆盖。手动结果写入配置旁 `config.yml.desktop-genres.json`，自动更新不会覆盖，且不改监控配置、启动入口或历史。
- 只读截图复用本地关联和缓存，不请求网络、不写类型。缓存过期时会在下次创建游戏条目、重新载入或重新关联海报时检查更新；不会随每次状态轮询重复抓取。

## 使用

- 网格 / 列表切换、名称或程序搜索，`Ctrl+F` 聚焦，`Esc` 清空。显示已结算的历史时长，不把待启动时间记作游玩时间。运行中的游戏会实时显示本局已玩时间（见[运行中计时与休眠暂停](#运行中计时与休眠暂停)）。
- 详情卡直接提供 HDR、手柄和倍速开关；名称、程序路径、参数、自动化开关、海报和类型编辑在“设置与管理…”二级面板。选中游戏后可编辑名称、HDR、倍速和启动入口；“保存设置”原子保存并热更新配置。“启动游戏”会先保存当前游戏的修改。
- 启动入口可为完整 exe、`.lnk` / `.url` 快捷方式路径，或 `steam://rungameid/数字`。参数和工作目录在展开区设置；Steam URI 不附带这两项。仅有进程文件名的旧配置需要补全启动入口；旧绝对 exe 路径默认可启动。
- 使用 Mod、平台启动器的游戏，选择原本使用的快捷方式。用于识别的程序仍填写实际游戏进程，两者可以不同。
- 顶部“添加游戏”或侧栏“游戏管理”打开程序添加、目录扫描和 Steam 扫描菜单；“扫描 Steam”读取本地游戏库，确认选中条目后导入。新条目使用 Steam 平台入口，重复导入保留已有条目的全部设置。
- 添加／管理菜单内的“扫描目录”选择本地游戏库或单个游戏目录，先只读扫描，再勾选批量添加。会预选每个目录的推荐程序，仍请检查名称和路径；同目录的其他程序作为备选，常见运行库、卸载器、崩溃上报器被排除。新游戏的 HDR 和倍速默认关闭，已有条目完整保留；不执行候选程序，也不持续监视目录。
- 默认只看“本机已安装”，其他分组为“本地未找到”“待确认”和“全部”。已知完整程序路径缺失才归入未找到；仅有程序名、无法确认的平台入口或访问错误归入待确认。Steam 本地清单可补充确认旧的程序名条目。切换分组不删除配置、草稿或历史，历史统计始终包含已卸载游戏。
- “从目录移除”需要确认，历史记录保留。关闭自动化后仍可普通启动，但不应用 HDR、倍速或计时。
- 海报优先使用工具缓存和 Steam 客户端本地缓存，缺少时从 Steam 官方站点自动下载。下载在后台执行，不阻塞游戏启动。

## 库内启动与外部启动

**库内启动**会在拉起进程前确认 HDR；进程被识别后进入`运行中`状态，按设置应用倍速和配套软件。HDR 游戏运行期间显示器预设让位。

**外部启动**（Steam"开始"按钮、桌面快捷方式、其他启动器）照常计时、应用倍速，并启动或复用已配置的 DS4Windows；库中显示`运行中·外部`，一样显示本局计时并优先排列。外部启动不切换 HDR，即使勾选了 HDR，也降级为显示器游戏模式（遵循 monitorMode 开关与日照规则）。已运行游戏不允许再次启动或运行中补切 HDR；需要前置 HDR 时请退出后从游戏库启动。监控启动时补扫到的进程也遵循外部启动规则；恢复快照保留原有启动来源。

跨重启的在途会话按快照里的启动来源恢复 HDR 资格，倍速和配套软件不受来源限制；升级前的旧快照没有标记时保留历史连续性口径。监控器启动时补扫到的游戏保持外部来源，不补切 HDR。休息提醒只看前台窗口是否为配置内游戏，与启动来源无关。

显示器预设（monitorMode）与 HDR 自动化互斥：库内启动且勾选了"启动前开启 HDR"的游戏在跑时，预设自动切换整体暂停；外部启动不因 HDR 勾选而暂停。无论启动来源，系统 HDR 已开启或状态无法确认时仍不做 DDC 读档或写档，确认 SDR 后恢复（见[显示器预设](monitor-mode.md#与-hdr-自动化的关系)）。

## Steam 海报

明确的 Steam App ID 来自已确认的海报关联、Steam 启动 URI / `.url`、本地 `appmanifest_*.acf` 或附近的 `steam_appid.txt`。安装清单优先于旁边的 ID 文件；名称搜索的自动关联使用下述置信度规则。

选中游戏后点击“匹配 / 重试 Steam 海报”，使用中文或英文名称搜索并选择对应版本，或填写 Steam 商店链接 / App ID。选择立即保存，可重试下载；“恢复自动识别”清除手动关联。搜索只发送输入的名称，不发送本地程序路径。无需 Steam 登录或 Web API Key。

“按名称补全海报”集中显示缺少封面的本机游戏，也可包括其他安装分组。选择游戏即可搜索，默认勾选“搜索后自动采用最佳匹配”，可关闭此选项只预览；“批量采用最佳匹配”处理当前范围内未关联的游戏。搜索合并中英文结果，并通过 Steam StoreBrowse 获取英文别名及游戏类型，例如 Astral Ascent 可关联中文“星界战士”。已确认的 DLC、画集、原声带等附属内容不参与自动选择。

自动选择要求名称相似度至少 90%，领先第二名至少 10 个百分点；忽略标点、空格、商标和快捷方式后缀，罗马与阿拉伯序号可对应。仅已确认的本体允许小幅拼写差异，序号、版本关键词不同或多个相近结果都保留人工选择；类型元数据不可用时只接受唯一规范化同名。调整搜索词不改变用于自动判断的游戏名称。已有海报关联不会自动覆盖，手动“使用选中的海报”仍可替换。关闭窗口取消剩余工作，已完成关联保留；网络失败可重试。

目录扫描最多读取 10,000 个目录、50,000 个条目、8 层子目录、1,000 个候选程序或约 25 秒，达到任一上限会明确提示缩小目录重扫。不跟随目录链接；不可读目录计数提示。它是基于程序文件、产品名及目录结构的候选识别，不保证所有 exe 都是游戏，导入前应确认。导入时重新检查路径，已消失的候选会拒绝整批变更。已知文件的存在状态在刷新时重查，Steam 安装清单最多缓存 30 秒。

官方竖版图形规格见 [Steamworks Library Assets](https://partner.steamgames.com/doc/store/assets/libraryassets)。客户端读取公开的 StoreBrowse 图形元数据，支持带版本哈希的图片路径，并以传统 library capsule 地址兜底。公开服务格式和资源可用性可能变化，获取失败时使用已有缓存或图标，不影响监控、计时和启动。

下载限制为两笔并发、每个 App ID 一次共享请求，单笔海报最大 5 MiB；解码验证后原子写入 `%AppData%\GameHelper\cache\steam-posters\<AppID>.jpg`。相同窗口不会在状态轮询时重复下载。失败标记退避五分钟；重新打开后可自动再试，手动匹配 / 重试可立即重试。已有有效缓存离线仍可使用。

手动关联单独保存在配置旁 `config.yml.desktop-artwork.json`，更新或关闭后保留，不修改 `config.yml`、启动入口或 HDR / 倍速设置。后台开机模式不创建游戏库，也不下载海报。

## 最近活动与刷新

各安装分组内优先显示正在运行的游戏，其后按最近一次已结束的游玩时间与添加时间的较新值排序。同一活动时间优先最近游玩；没有日期的旧条目按配置列表顺序倒序稳定兜底，不将其视为真实添加时间。新游戏通过添加、Steam 或目录导入时记录可选 `addedAt`（ISO 8601，含时区），重复导入及编辑保留原值；旧条目不补造日期。最近游玩取有效历史会话的结束时间，未来或无效记录不参与排序。

后台状态轮询不禁用菜单，保留没有变化的列表项、选择、草稿和海报；只有实际变化才调整对应条目。保存等主动操作仍显示忙状态，操作前发出的旧轮询响应不会覆盖其结果。海报对话框的列表在搜索、禁用与重新启用时保持深色背景。

## 运行中计时与休眠暂停

运行中的游戏在卡片徽章、列表状态列和右侧详情显示"运行中 · 00:12:34"，卡片下方另有绿色"本次已玩"一行，逐秒推进；游戏退出或该会话结束后恢复普通状态文本。计时来源是监控进程的本局会话开始时间：界面轮询到一次后用本地时钟自行推进，秒级刷新不产生后台通信。

系统进入睡眠或休眠时计时暂停：唤醒后监控把整段休眠时长从活跃会话的开始时间中剔除，休眠时间不计入游玩时长，会话本身跨休眠保留（结合[in-flight 快照恢复](etw-recovery.md)），落盘时"开始时间"为剔除休眠后的有效开始时间，保持时长等于起止差。监控进程未运行时没有计时，也没有休眠剔除问题。

## PS 手柄兼容：启动前运行 DS4Windows

在游戏详情中勾选“启动前运行 DS4Windows（PS 手柄）”，路径预填为本机的 `D:\Program Files\DS4Windows\DS4Windows\DS4Windows.exe`，也可选择其他位置。按游戏独立保存，默认关闭；仅从本游戏库启动时生效，普通 exe、快捷方式和 Steam 入口均支持，与游戏自动化开关独立。

启动前先检查游戏与 DS4Windows 路径，之后依照既有 HDR 流程，先确保 DS4Windows 运行，再发起游戏启动。只复用完整路径一致的进程；新启动请求隐藏窗口并禁止分配控制台，最多等待 5 秒进入 GUI 空闲状态。程序不存在、启动失败或未能完成启动时会提示错误，不继续启动游戏，已开启的本工具 HDR 会按既有失败流程恢复。GUI 空闲不代表驱动、手柄连接或虚拟手柄已经就绪；这些仍由 DS4Windows 的配置决定。游戏退出或 GameHelper 重启不会关闭它。

YAML 对应 `games[].launch.ds4WindowsPath`，省略或在界面取消勾选即关闭。例如：

```yaml
launch:
  target: steam://rungameid/620
  ds4WindowsPath: C:\Tools\DS4Windows\DS4Windows.exe
```

## HDR 和启动失败

开启监控 → 确认系统 HDR → 原入口启动 → 等待游戏进程 → 真实计时和倍速。HDR 查询失败或未能确认开启时不启动游戏。平台入口返回不等于游戏成功运行；两分钟内未识别到已登记进程会显示超时并释放 HDR。启动中的同一游戏不能重复发起。

最后一个需要 HDR 的游戏及待启动请求结束后，仅恢复本工具原先开启的 HDR。用户原本已打开的 HDR 保持开启。归属与启动截止时间随会话快照跨程序重启保存，恢复时不重复启动游戏。HDR 已开启或状态未知期间不尝试 DDC 显示器预设切换。

从 Steam 等外部入口直接启动仍可被监控并自动应用倍速、显示器预设和配套软件，但不会切换 HDR。游戏需要前置 HDR 时应从游戏库启动。

## 保存、草稿与冲突

界面修改先成为草稿，不立即改写 `config.yml`。草稿单独保存在同目录 `config.yml.desktop-drafts.json`，包括尚未输入完成的倍率文本；关闭、崩溃或部署重启后继续编辑。“重新载入”确认后放弃草稿。不同配置的游戏库互不影响，同一配置只打开一个编辑窗口。

外部修改或 CLI 修改同一游戏后，旧草稿保存会报告冲突。重新载入最新设置再修改，避免覆盖其他入口的更新。通信超时不会自动重试保存或启动；刷新确认实际状态后决定下一步。

## 配置格式

```yaml
games:
  - dataKey: my-game
    executable: C:\Games\MyGame\game.exe
    displayName: My Game
    enabled: true
    hdr: true
    launch:
      target: C:\Games\MyGame\mod-loader.exe
      arguments: -windowed
      workingDirectory: C:\Games\MyGame
```

`launch` 可省略；绝对 `executable` 路径作为默认入口。它不改变 `dataKey`、进程匹配或历史记录身份。保存运行中的游戏设置时，倍速在下一次真实启动时应用。

## 开发与验证

先正常启动 ConsoleHost，再执行 `dotnet run --project GameHelper.Desktop`。自定义配置使用 `--config <完整路径>`。`GAMEHELPER_DATA_DIR` 仍按既有隔离规则追加 `GameHelper` 子目录。

发布 ConsoleHost 的 win-x64 产物会在 `desktop/` 一起发布 WPF；不能把另一种运行时布局逐文件覆盖进去。完整部署仍执行 `scripts/verify-on-machine.ps1`。脚本会一并原子换入两个入口，重启原本打开的游戏库，并通过实际 IPC 查询验证连接。

只读验收支持 `GameHelper.Desktop.exe --config <沙盒配置> --snapshot <输出目录>`：不激活地显示渲染窗口，连接指定隔离实例，输出网格、列表、空搜索和最小窗口截图后退出，不保存设置或启动游戏。`--check <输出JSON>` 执行无窗口的只读连接探针。

快照还输出 `installed-default.png`、`missing-games.png`、`unknown-games.png` 以核对安装分组，`launch-options.png` 展示滚动后的启动设置；后续布局截图会选择全部分组，以覆盖隔离测试中已不存在的示例路径。设置 `GAMEHELPER_TEST_SCAN_DIRECTORY` 可附加只读扫描与 `directory-scan.png`，不会导入候选。

快照模式仅用已有海报缓存，不联网。实际下载与渲染回归需显式设置 `GAMEHELPER_TEST_STEAM_POSTER=1`，测试通过隔离数据目录启动不激活的真实 WPF 窗口，再检查缓存和只读截图；默认测试用 HTTP 替身验证缓存、坏响应、限流、大小限制和取消，不依赖网络。

`--background` 无窗口连接或启动监控；可组合 `--check` 返回就绪信息和运行时 PID。`--restore` 恢复游戏库但不激活窗口。后台运行时的输出在配置旁 `config.yml.runtime.log`，超过 5 MiB 时下次启动轮转为 `.previous`。排错仍可手动从终端运行 ConsoleHost 命令。

外部启动的配套软件在游戏进程被识别后启动，不保证先于游戏初始化；原程序已运行则复用。配套软件失败记录运行时警告，不阻断计时、倍速和显示器预设。库内启动仍先启动配套软件再拉起游戏，失败时不启动游戏。

## 横图与次级操作
