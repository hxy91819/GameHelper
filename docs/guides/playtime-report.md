# 年度 / 季度游玩报告

打开游戏库 **游玩档案 → 年度 / 季度报告**，输入年份，选择年度或第一至第四季度，点击 **生成报告**。展开正文查看，点击 **导出 Markdown** 保存本地文件；不提供图片导出。

报告直接使用已有历史快照，不改写历史。SQLite 激活后，会话与其历史修订在同一个短读事务读取，连接释放后复用原 Core 年度／季度聚合与渲染；未激活回退旧存储时行为不变。统计包括总时长、活跃日期数、游戏数、次数、Top 5、最长单局、月分布、周分布、最常游玩时段、首次登记的新游戏、本期通关，以及上一自然期间的时长、天数、游戏数和通关数对比。旧游戏没有 `addedAt` 时不推断加入日期；已移除游戏仍按 DataKey 计入历史。

## 统计口径

- 自然年为本地 1 月 1 日（含）至次年 1 月 1 日（不含）；季度为 1–3、4–6、7–9、10–12 月。
- **跨午夜、跨季度、跨年会话整条归本地结束日**，不切分时长，与游玩档案一致；沿用历史保存的分钟数。UTC 时间按注入时钟的本地时区转换；没有时区的历史维持本地时间含义。
- 只统计已结束会话，排除未来结束、负分钟和结束早于开始的记录。零分钟记录仍计入次数、游戏数和活跃日。
- 周一开始，报告首末周截断到期间边界。月份包含零值月份。
- 最常游玩时段按 **本地开始小时累计整局分钟数**，不是逐小时在线时间估算；同分钟数优先较早小时。最长单局按保存分钟数，Top 5 同分按 DataKey 排序。
- 年度对比上一完整自然年，季度对比上一完整自然季度（第一季度比较上年第四季度）；上期为零时不显示百分比。
- 当前或未来期间标为尚未结束，只含截至当前的已结束会话；对比仍用完整上期，不外推，不调整成同比天数。
- 不叠加进行中的计时，多游戏会话可能重叠。

通关信息由桌面手帐独立存储；报告只读取已记录的通关状态和日期，不根据启动或时长猜测，也不改动游戏详情编辑区。

## 本期通关

报告读取本机 Desktop 手帐：通关日期落在所选期间内且状态为 **已通关** 或 **全成就** 的条目进入“本期通关”，按日期升序显示名称、日期和状态；有短评时在同一条目后显示。没有条目时整节不出现，未开始、在玩、搁置以及没有通关日期的条目不计入。通关条数与上一完整自然年／季度比较，显示变化值。

手帐仍只保存在配置旁的 `config.yml.desktop-journal.json`，不写入 `config.yml`，也不经过游戏库 IPC。报告页生成统计后由 Desktop 侧按 `DataKey` 合并手帐，Markdown 导出使用同一份合并结果；当前游戏库找不到显示名时回退为 `DataKey`。手帐短评只用于页面和导出，不进入大模型请求。

## 可选大模型点评

默认未配置即关闭，程序统计不依赖模型。全局设置填写兼容 OpenAI 的接口根地址（含服务商要求的 `/v1` 等前缀）、模型和 API Key，保存后在报告页主动点击 **生成大模型点评**。API Key 用密码框掩码显示；全部清空保存可关闭。

```yaml
report:
  llm:
    baseUrl: https://example.com/v1
    model: your-model
    apiKey: your-local-key
```

请求 `POST <baseUrl>/chat/completions`，API Key 只作为 Bearer 认证头。总超时 60 秒，可取消；HTTP 错误、网络失败、空响应、无效响应只显示错误，保留统计和 Markdown 导出。不会自动重试，也不会后台生成或保存点评；点评仅保留在当前窗口，导出时可包含。

只发送期间、是否未结束、时长／天数／游戏数／次数及上期汇总、Top 5 的 DataKey 与分钟数、最长单局的 DataKey 与分钟数、月／周汇总、小时分布、新加入游戏的 DataKey、本期通关数与通关游戏显示名。**不发送其他游戏显示名、文件路径、配置、原始会话、精确起止时间、通关短评或其他本地元数据**。模型内容标注为点评，程序统计不被它覆盖。

`apiKey` 保存在本机 `config.yml`。现有 [sync](sync.md) 只上传受管统计文件，不上传 config.yml，因此无需改变同步内容，也不会同步此密钥。不要自行把含密钥的配置加入远端备份。

## 验证边界

Core 聚合使用注入 `TimeProvider`，测试固定时钟及本地时区。客户端接收可注入 `HttpClient` 和时钟，假 HTTP 测试断言统计白名单、认证头、超时、取消和错误脱敏。通关合并测试只使用固定 `DateOnly`，覆盖期间边界、全成就、其他状态、空节隐藏和导出文本，不依赖墙钟。未配置 report 的旧配置写回继续使用已有固化字节样本验证，不新增空 report 段。

本批次不提前迁移 Desktop 手帐或启用评分；现有手帐仍按上述路径合并。批次 5 迁移侧数据时才将报告所需手帐、评分和会话并入同一个读事务，避免新旧写权混用。
