# Windows 实机验收：主机模式与手柄

给已经在 Windows 上、准备带用户做验收的 Agent。产品行为以 [游戏库](game-library.md)（手柄操作、手柄支持信息、全屏主机模式）、[桌面手柄输入](../architecture/controller-input.md) 和当前 main 的界面文案为准。本文只排步骤和判定，不另定行为。

## 给 Agent 的说明

目标：用户在自己的机器上，用手头的 Xbox、PS4（DS4）、PS5（DualSense）把手柄导航、游戏库标记和全屏主机模式走一遍。你引导，用户操作，你判定并留下可交回的记录。

引导方式：一次只给一步。等用户回报看到的现象，再对照该步的「预期」判通过或失败。不要把后面的步骤提前做完。键鼠是文档中的备用；某步只有键鼠能完成时，该步记失败并写明手柄无响应。用键鼠退出卡死画面可以，不把已经失败的步骤改成通过。

失败时记下现象、手柄型号、连接方式（USB 或蓝牙），并请用户截图。不在这台机器上改代码，不改 DS4Windows、HidHide、Steam Input 的配置，不往发布目录里单独拷文件。

没有的手柄、第二块屏幕，或用户拒绝的可选动作（真的关机、真的结束游戏、等待满 10 分钟打分），记跳过并写原因，不算失败。会改到用户设置的步骤，按该条的「恢复」做完再继续。

结果记在本文件末尾：复制「结果表」模板，追加到「运行记录」下面再填。用户指定了别的位置就记到那里，并在运行记录里写明位置。做完把结果交回管家：能推 main 就只提交这次验收记录；不能推就把填好的记录贴给用户。

建议顺序：准备 → C1 → C6 → C7 → C8 → C9 → C17 → C2 里还没覆盖的连接 → C3 → C4 → C10 → C11 的 exe → C5 → C13 → 退出后看 C11 恢复 → C11 的 Steam URI → C12 → C14 → C15。顺序可以按手头设备改，每条仍单独记录。

## 准备

完成标准：部署脚本成功退出，健康检查原文出现，并且下面的环境都已写入准备记录。脚本失败或健康检查没有通过就停，把完整输出记入准备，不开始用例。

1. 在 GameHelper 仓库执行 `git pull --no-autostash origin main`。记录 `git rev-parse --short HEAD`。
2. 先问用户现在有没有正在被 GameHelper 监控的游戏。然后执行 `powershell -File scripts\verify-on-machine.ps1 -SkipVerify -Restart`。部署会重启 GameHelper，不关电脑。
3. 核对脚本输出里有这两句：`Deploy health check passed (integrity, data directory, ETW).`、`Desktop library IPC health check passed.`，以及 `New GameHelper instance is running (PID …).`。打开发布目录 `GameHelper.ConsoleHost\bin\Release\net8.0-windows\win-x64\publish\deploy-manifest.json`，核对其中的 SHA 与当前 HEAD。工作区不干净时脚本会警告，照原文记下，不要为了验收去改那些文件。
4. 记录 Windows 版本（设置 → 系统 → 关于，或 `ProductName` / `DisplayVersion`）、每只手柄的型号和 USB 或蓝牙、是否安装了 DS4Windows、HidHide、Steam，以及 Steam Input 是否开着。型号以用户在「蓝牙和其他设备」里看到的为准。
5. SQLite 与在途会话沿用 [桌面工作簿](../steward/desktop-and-capabilities.md) 里仍开放的那条 Windows 待办，不另做一套检查。重启后托盘没有标题「GameHelper 存储提示」、正文「SQLite 迁移未激活，继续使用旧存储：…」或「SQLite 已保存；旧版兼容投影失败，暂不能降级：…」的气泡，即算迁移与投影正常。部署前若有受监控游戏，重启后同一局仍显示运行中，时长不从零另起一局（见 [验证与部署](verify-and-deploy-workflow.md) 的跨重启会话续算）。当时没有在途游戏则续算记跳过。

记录项：HEAD、manifest SHA、Windows 版本、手柄清单、DS4Windows / HidHide / Steam / Steam Input、健康检查原文、SQLite 气泡、续算结果。

## 用例

手柄按键对照：Xbox 为 A / B / X / Y、LB / RB、Start、方向键或左摇杆；PS4 / PS5 为 × / ○ / □ / △、L1 / R1、Options。下文 Xbox 名在前。方向键长按约 400ms 后会每 90ms 重复一格；点按一次只动一格。确认、返回、菜单不连发。左摇杆要推出死区（约 49%）才算方向，斜向只取主轴。

### C1 游戏库手柄导航与启动

在桌面游戏库（不是全屏主机模式），窗口在前台。

1. 方向键或左摇杆移动海报。网格里上下按当前列数跳；窄窗口 3 列，否则 4 列。点按一次只动一格。
2. LB / RB（L1 / R1）在网格里一次跳过约三行。若当前是列表，先切回网格再测。
3. Start / Options 打开「游戏设置与管理」。B / ○ 关闭它。原生文件选择框仍用键鼠，这不是失败。
4. 选一款用户同意启动的已安装游戏，A / × 启动。这与双击海报相同：先保存当前游戏的修改，成功后游戏库最小化，前台让给游戏。
5. 重新点回游戏库后，先松开按键再按。按住确认键越过重新激活的瞬间不会启动游戏。

预期：选中跟着当前手柄走；一次点按不多走一格；设置页能开能关；启动后游戏库最小化。失败时记下是哪一步、画面停在哪。

记录项：布局（网格/列表）、列数、启动的游戏名、是否最小化。

### C2 三类手柄的 USB 与蓝牙

对用户实际拥有的组合各做一次：Xbox、DS4、DualSense，能接 USB 就测 USB，能接蓝牙就测蓝牙。没有的组合跳过。C1 已经覆盖的那一格记「同 C1」，不必重做。

每格只做：前台游戏库里点按方向一次，选中移动一格；再点一次 A / ×，若用户不同意真的启动，就改为打开并关闭「游戏设置与管理」。

预期：该连接下方向与确认有响应，一次点按只动一格。蓝牙 PS 手柄不应被 GameHelper 改掉灯条模式（游戏还没启动时，灯条保持用户原来的样子）。

记录项：每格通过、失败或跳过。

### C3 热插拔与换手柄接管

需要两只手柄。只有一只则热插拔仍可测，换手柄接管跳过。

1. 用甲操作游戏库。拔掉甲，再插上，先全部松开，再按方向。选中可以继续移动。
2. 甲、乙都连着。甲按住确认键，乙在 0.5 秒内按方向：选中不动，游戏不启动。
3. 两只都松开，摇杆回中，静候超过 0.5 秒。乙新按一次方向：选中移动一格。
4. 甲仍在活动时，乙按住确认键不放，一直等到超过 0.5 秒：不启动、不重放这下确认。松开后，乙再新按一次方向，才由乙接管。

预期：空闲满 0.5 秒后的新按下才换手柄；冷却期间按住的旧确认不会在到期时补发。不要求两只同时操作。

记录项：两只手柄的型号与连接；第 2–4 步各自的现象。

### C4 DS4Windows 或 Steam Input 开着时不双重导航

用户没有开 DS4Windows，也没有开 Steam Input 时，整例跳过。不要为了本例去安装或改它们的配置。

开着其中之一，物理手柄和它的虚拟手柄会同时出现。在游戏库点按一次方向。

预期：选中只移动一格，不是两格。GameHelper 同时只读一只设备；虚拟 Xbox 按 Xbox 类型处理。延迟镜像不应在物理键松开后的 0.5 秒内再走一格。

记录项：开着的软件、点按一次实际移动的格数。

### C5 游戏运行时不干扰手柄

接在一次用户同意的启动后面做。游戏已在前台、GameHelper 已最小化。

1. 在游戏里移动视角或菜单，确认手柄输入进的是游戏。
2. DS4 / DualSense 看灯条：仍由游戏或手柄自己控制。Xbox 没有灯条，此项记不适用。
3. 不要求震动。GameHelper 不启用震动。

预期：最小化后 GameHelper 放开手柄。游戏内没有双份输入，灯条不被 GameHelper 抢走或改写。

记录项：游戏名、输入是否只进游戏、灯条现象。

### C6 手柄支持标记、手动设置、筛选，以及 DS4Windows 改名

在桌面游戏库。库里没有某一档时，那一档跳过，不要改 AppID 或造数据。

标记对照：

| 来源 | 详情与海报上的文字 | 海报底部红色「不支持手柄」 |
| --- | --- | --- |
| Steam 完整支持 | 完整支持手柄 | 无 |
| Steam 部分支持 | 部分支持手柄 | 无 |
| Steam 有条目但未标注 | 不支持手柄；说明为「Steam 未标注手柄支持」 | 有 |
| 无 AppID，或请求失败 | 手柄支持未知 | 无 |
| 手动支持 / 手动不支持 | 支持手柄（手动） / 不支持手柄（手动）；说明含「用户手动设置，优先于 Steam。」 | 仅手动不支持有 |

详情里可同时看到 DualShock、DualSense 声明（有则显示「Steam 声明 DualShock 支持」「Steam 声明 DualSense 支持」）。

1. 对照上面，看用户库里实际有的档。红色只出现在「不支持」和「手动不支持」。
2. 打开该游戏的「游戏设置与管理」。按「支持手柄」「不支持」或「清除设置」。手动结果立刻优先于 Steam。测完按「清除设置」恢复。
3. 搜索旁的「···」里点「只看不支持手柄」。列表只剩红色这档（未标注或手动不支持），不含部分支持、未知、完整支持和手动支持。再点「清除能力筛选」。
4. 只核对改名，不拨开关。游戏详情卡写的是「启动 DS4Windows」，副文案「启动时按开关运行或退出」。设置页预设是「预设：DS4Windows（PS 手柄）；未勾选时启动游戏会关闭它」。不应再看到旧名「手柄支持」当作这个启动预设。配置字段仍是 `games[].launch.ds4WindowsPath`。未勾选表示启动时关闭已运行的 DS4Windows，所以不要为了验收去拨动它。

记录项：看到的档与游戏名、手动设置是否已清除、筛选结果、详情卡与设置页的实际文案。

### C7 主机模式入口与手柄切换

1. 游戏库顶栏「主机模式」（「刷新」左边）进入全屏窗口，标题「GameHelper 主机模式」，顶上有「◈ GAMEHELPER / 主机模式」。
2. B / ○ 或系统菜单的「退出主机模式」回到桌面游戏库。再从托盘菜单「主机模式」进入。托盘里该项在「打开 GameHelper 游戏库」下面。
3. 退出后打开侧栏「全局设置」，勾选「启动 GameHelper 游戏库时直接进入主机模式」，点「保存全局设置」。关掉游戏库，从桌面「GameHelper 游戏库」或托盘「打开 GameHelper 游戏库」再打开，应直接进入主机模式。`config.yml` 里 `consoleModeOnLibraryOpen` 为 true。测完取消勾选并再次保存，确认该键回到 false（默认关）。
4. 游戏库前台且没有弹窗时，同时按 View/Back + Start（PS4：Share + Options；PS5：Create + Options），应进入主机模式；全部松开再按，应回桌面库。交换两键先后顺序重复，长按不应来回切换，也不应额外打开设置或系统菜单。桌面有弹窗时先 B / ○ 返回。单独 Start / Options 在松开时仍打开原设置或菜单。
5. 切到其他应用前台，再按组合键，不应激活 GameHelper 或弹出主机模式。此项不要求在正在游玩的游戏里操作，普通应用即可。

已有窗口时，Desktop 的 `--console-mode` 也会请求进入。三个界面入口都通过时，这一命令可以不做，跳过不算失败。

记录项：入口与双向切换的现象、长按/按键顺序/失焦结果、配置键恢复后的值。

### C8 页签与扳机翻页

主机模式主页，底部提示里页签是 LB / RB 或 L1 / R1。

页签从左到右：全部、最近、未通关、支持手柄。旁边另有「搜索 / 屏幕键盘」，那不是页签。RB 往后一档，LB 往前一档，到头后循环。标题形如「今晚，继续冒险。 / 全部」。

含义：最近是近 30 天有游玩的游戏；未通关排除手帐「已通关」和「全成就」；支持手柄只含完整支持或手动支持，不含部分支持。排序是最近游玩在前，没玩过的在后。桌面库当时的搜索和筛选不改变这份列表。

预期：LB / RB 只改页签，不在海报上跳三行（跳三行是桌面库）。键盘 PageUp / PageDown 与 LB / RB 相同，只作为备用。

在至少有两屏游戏的主页按 R2 / RT，选择与海报视口应向后跳一屏；L2 / LT 向前。首尾不循环，窗口变窄时每页卡片数随之减少。持续按住只翻一页，松开再按才下一页；轻触扳机不应抖动翻页。翻页不改分类页签。进入详情或打开覆盖层时，不用扳机翻主页。

视觉回归：未选中的名称、时长、支持标记应清晰可读，红色「不支持手柄」仍可辨；选中背景只包住卡片内容，不延伸至底部。桌面先切浅色再进入主机模式，仍应显示一致的深色高对比布局。无需启动游戏。

记录项：四档各自是否切得动、扳机翻页与末页是否正确、长按是否重复，以及和桌面筛选是否互不影响。

### C9 屏幕键盘搜索

1. 主页按 Y / △，或点「搜索 / 屏幕键盘」。标题是「按名称搜索」。
2. 方向键选字符，A / × 输入，X / □ 退格，Y / △ 或「完成」生效，B / ○ 或「取消」放弃。键位为 A–Z、0–9、空格、清空、完成、取消。
3. 输入一个能命中部分游戏的英文或数字片段，完成。列表按名称包含匹配，忽略大小写，并与当前页签叠加。清空或完成后空查询，恢复当前页签的全部游戏。取消则保持打开键盘之前的查询。
4. 搜索最多 100 个字符，再输入不再增加。这不是故障。

预期：过滤只发生在主机模式自己的查询上。中文输入看文末已知限制，不要判失败。

记录项：查询词、过滤前后的游戏数量、取消是否保留旧查询。

### C10 详情与非完整支持的启动确认

主页 A / × 进入详情，不立刻启动。详情里能看到时长、手帐状态、最近一次评分、手柄来源说明，以及当前启动设置、DS4Windows 状态和系统菜单设置入口提示。设置操作见 C18。

再按一次 A / ×：

- 部分支持、Steam 未标注、手动不支持：先出现「部分支持或不支持手柄，请备好键鼠。确认仍启动 / 返回取消」。再按 A / × 才启动，B / ○ 取消确认并留在详情。
- 完整支持、手动支持、未知：不出现这段确认，再按 A / × 直接进入启动。未知不要被判成漏提示。

本条只要确认框对得上。真的启动放到 C11；若这里误启动了，记下游戏名，接着按 C11 的预期看，不要强行关掉除非用户同意。

记录项：游戏名、标记档、有没有确认框、B 是否取消。

### C11 exe 与 Steam URI：最小化、恢复、打分邀请

需要用户同意真的启动。库里只有 exe（或会返回 PID 的快捷方式）或只有 `steam://rungameid/数字` 时，缺的那一种跳过。启动前不要从 Steam 或其他入口再开同一款游戏。

1. 从主机模式确认启动。覆盖层为「启动中…」和「正在等待游戏进程 · 返回可关闭提示」，状态栏「正在等待 <名称> 启动」。此时窗口还不要最小化。
2. 等待期间按 B / ○：覆盖层关掉，状态仍是「正在等待 <名称> 启动」，不能再发起一次启动。
3. 监控确认这次请求的进程后，主机窗口最小化，手柄输入释放。exe 或返回了 PID 的快捷方式按该 PID 对应；Steam URI 或没返回 PID 的快捷方式，只认请求前没在运行、两分钟内第一次出现的新会话。
4. 正常退出游戏后，主机模式应恢复至前台并取得焦点；直接按手柄方向/确认应立即响应，无需先点窗口。再从桌面库启动隔离替身，停留统计页或最小化后退出替身，桌面库也应恢复并可直接操作。仅结束本次启动的会话触发一次，不使用外部游戏验证抢焦点。
4. 退出游戏。主机窗口恢复到前台。
5. 打分：现有邀请条件是真实结束、本局至少 10 分钟、还没评过。都满足时，恢复后约 15 秒内出现「本局体验如何？」，默认 3 星。左右改星，A / ×「提交评分」，B / ○「跳过」，X / □ 或「填写想法」打开「本局想法（可留空）」，想法最多 2000 字，可空。跳过不写记录。不足 10 分钟或已评过则不出现邀请，这是通过。用户不想等满 10 分钟时，打分记跳过。

预期：未确认运行前不最小化；确认后最小化；这次进程退出后恢复。两分钟内从别处启动同一游戏会被当成这次启动，那是已知限制，不要记失败；验收时避免这样做。

记录项：入口类型（exe 或 Steam URI）、最小化与恢复的时机、邀请出现与否、本局大概时长。

### C12 两分钟超时提示

不要用 C11 那次已经成功的启动来等超时，也不要改启动配置制造超时。选一款启动后不会马上出现被监控进程的游戏（例如停在启动器里、用户不再继续）。库里没有这种游戏就跳过。

启动后什么都不按，等到约两分钟。

预期：覆盖层关掉，状态栏出现「等待游戏进程超时，请返回详情检查启动状态。」提示留到返回或再次尝试。之后迟到的进程不再让主机窗口最小化或恢复。立即失败并显示启动错误的，不是这条超时文案；记下实际错误，本条跳过，不要改判成超时失败。

记录项：游戏名、实际等待时间、状态栏原文、迟到进程有没有抢走前台。

### C13 回到游戏与结束游戏

游戏已从主机模式启动且仍在运行时，打开它的详情。按钮为「回到游戏」和「结束游戏（需确认）」。底部提示：A 回到游戏，X 游戏设置，B 返回，结束游戏从系统菜单进入。

1. A / ×：回到游戏窗口，主机模式最小化并释放手柄。
2. 再打开详情，从系统菜单选择「结束当前游戏（需确认）」或点详情「结束游戏（需确认）」。确认文案为「确认结束 <名称>？」并说明未保存进度可能丢失。按钮是「确认」「取消」。先按 B / ○ 取消，游戏仍在；直接按 X / □ 应打开自动化设置，不结束游戏。
3. 只有用户明确同意才按 A / × 确认结束。结束只作用于监控确认的那个进程。用户不同意则结束动作跳过，确认框本身可以记通过。

记录项：回到游戏是否切到前台；确认框原文；是否真的结束。

### C14 系统菜单：退出、HDR、休息提醒

Start / Options 打开「系统菜单」。上下选择，A / × 确认，B / ○ 或再按一次 Start / Options 关闭。菜单包括退出主机模式、当前游戏设置、主显示器 HDR（托盘同款文案「主显示器 HDR：已开启 / 已关闭 / 状态未知」，不可用时是「HDR：不可用」）、「暂停休息提醒 30 分钟」或「恢复休息提醒」，以及留给 C15 的三项电源操作。无法执行的项是禁用的，禁用与托盘里同一动作一致即可。

1. 核对 HDR 与提醒的文字、能否按下，和托盘菜单一致。真正切换 HDR 或暂停提醒前先问用户。用户拒绝就该项跳过。若暂停了提醒，测完在菜单里「恢复休息提醒」。
2. 选「退出主机模式」，回到桌面游戏库。可以再从顶栏进主机模式，以便做后面的用例。

预期：显示器 HDR 临时开关与 C18 的游戏自动 HDR 配置明确分开；执行临时动作不改游戏的启动偏好。

记录项：菜单原文、禁用项、是否动过 HDR 或提醒、退出后落在哪。

### C15 睡眠、重启、关机

可选。先让用户保存所有工作。用户没明确同意就整例跳过，不算失败。关机放在最后，而且要单独再问一次；它会结束这次验收。

同意后打开系统菜单，选「睡眠」「重启电脑」或「关闭电脑」。必须先看到二次确认，而不是立刻执行。没有游戏在跑时，文案是「确认睡眠？」或对应的重启、关机问句。有游戏时列出「正在运行：…」；睡眠写「睡眠会暂停游戏。」，重启和关机写「这些游戏将被关闭，未保存的进度可能丢失。」A / ×「确认」，B / ○「取消」。

先按取消，确认电脑没有睡眠或关机。只有用户要看真实效果时才确认。失败会在画面上显示错误，不要另想办法绕过 Windows。

记录项：做了哪一项、确认文案、取消是否留下电脑、真实执行的结果。

### C16 多显示器与高 DPI 全屏位置

先把游戏库放到要验收的那块屏幕上，再进主机模式。窗口按游戏库所在显示器的整块边界铺满（含任务栏那一截），用游戏库窗口的 DPI 换算位置。

1. 只有一块屏：看四边是否贴齐，没有缝，也没有超出。记下缩放比例；100% 也可以判本步通过。
2. 有第二块屏：把游戏库拖到非主屏再进入。全屏应在那一块上，不跨到另一块，也不缩在工作区内露出一圈任务栏。两块 DPI 不同时各看一次。没有第二块屏则这一步跳过。

记录项：屏幕数量、每块缩放、全屏落在哪一块、有没有缝或溢出。

### C17 按键提示随当前设备切换

主机模式底部的提示是文字，没有单独的按键图片。当前设备是 PlayStation 时用 PS 名称，否则（含 Xbox 和未知类型）用 Xbox 名称。虚拟 Xbox 保持 Xbox 名称。

主页应对上：

- Xbox：`左右 浏览   A 详情   B 退出主机模式   Y 搜索   LB / RB 页签   Start 系统菜单`
- PlayStation：`左右 浏览   × 详情   ○ 退出主机模式   △ 搜索   L1 / R1 页签   Options 系统菜单`

换一只另一类型的手柄：全部松开超过 0.5 秒后，用新手柄按一下方向，底部提示改成新设备的那一套。HidHide 或虚拟驱动让物理 PS 手柄不可见、只剩虚拟 Xbox 时，保持 Xbox 文案是通过；PS 文案记跳过并写明原因。

桌面游戏库侧栏也有组合键及前台生效范围提示；动态 A / × 等操作提示仍以主机模式底部为准。

记录项：每只当前设备下底部原文。

### C18 主机模式游戏设置

用户正在玩游戏时先跳过本条保存，或只在隔离配置中验证，不改当前游戏配置，不测试真实 HDR、DS4Windows 或倍速。

1. 选择一款未运行的游戏，在主页直接按 □ / X，或在详情按同一键，也可 Start / Options →「当前游戏设置」。三种入口应显示同一游戏的自动化设置，B / ○ 取消后回到原画面；核对标题中的游戏名。本页读取已保存配置，桌面未保存草稿不应被提前提交。搜索键盘里的 □ / X 仍是退格，评分页仍是填写想法。
2. 上下选择自动 HDR、启动 DS4Windows、倍速、倍率；左右切换开关，倍率每次变化 0.1×，在 0.1–10× 截止。B / ○ 取消再打开，原配置不变。
3. 记录原值，在用户允许保存的配置中修改并「保存设置」，应显示成功反馈；重新打开可读到新值，再恢复原值并保存。DS4Windows 路径与 CE 配置仍在桌面编辑；没有可用启动入口时启用 DS4Windows 应给出可操作的错误说明。
4. 若有第二窗口修改了同一游戏，旧面板保存应报告冲突并保留本页调整，不覆盖新配置。「重新载入已保存配置」放弃本页调整并读取新值。

预期：仅保存配置，不启动游戏、不立即启停 DS4Windows、不立即注入 CE。DS4Windows 与倍速在下次启动应用，HDR 在后续自动调度应用；显示器 HDR 临时切换不属于本页操作。保存后桌面未保存草稿仍保留，若过时则走原冲突处理。

记录项：目标游戏、取消/保存/重载结果、是否恢复原值、冲突结果；无法安全验证的项记跳过。

## 已知限制

下面的现象记通过，并在现象里写「已知限制」：

- 屏幕键盘只有英文字母、数字和空格，没有中文输入法。游戏名只有中文时，搜索可以跳过。
- 主机模式只编辑游戏的自动 HDR、DS4Windows 开关和倍速；路径、CE 环境及其他设置仍在桌面编辑。
- 手柄模式切换只在 GameHelper 前台生效，游戏中不监听，也不负责从后台唤起窗口。
- 两分钟等待里，若从 Steam 或其他入口启动了同一款游戏，也会被当成这次主机模式启动。
- 没有 AppID 的游戏显示「手柄支持未知」，不显示红色「不支持手柄」，启动前也不确认。
