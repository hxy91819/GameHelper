# 游玩档案

打开 WPF 游戏库侧栏的 **游玩档案**。统计直接读取既有历史，不修改 CSV、游戏配置、草稿或监控开关；私人手帐单独保存在 Desktop 侧。

## 页面

- **总览**：所选时段的小时数、已结束会话数、有记录的日期数和游戏数。平均单次及最长单次按历史分钟数计算；有限时段与紧邻的前一个同长度自然日窗口比较。“最常玩”卡片显示时长第一的游戏、其海报、时长与本期占比环。
- **时间轨迹**：7 / 30 / 90 天按日显示；全部历史的总览涵盖所有记录，趋势单独显示最近 12 个月，并标明范围。悬停柱形查看日期及分钟数。
- **游戏排行**：按时长默认排序，显示游戏海报缩略图、次数、占比和最近游玩日期；无海报时以首字母占位。可按名称 / DataKey 搜索，点击列标题按真实数字或日期排序。最多显示前 1000 款，超过时明确提示，整体统计仍涵盖全部游戏。
- **游玩节奏**：显示当前时段的活跃天数、活跃日均、次数、最长单次和周一至周日时长分布。点击排行游戏或选中后按 Enter，只筛选这一汇总；再次点击同一游戏取消。点击日历日期查看该日汇总（可在所选时段之外），再次点击取消；“清除”同时清除游戏与日期。总览、趋势和排行始终保持所选时段的整体口径。
- **游玩日历**：置于时间筛选上方，始终展示全部游戏最近约一年的记录，不受 7 / 30 / 90 天或全部筛选影响；左侧从周一对齐，覆盖 365–371 天。悬停查看当天的会话数和分钟数，点击查看当日汇总（保留已选游戏条件），再次点击取消。颜色分级为有记录且少于 30 分钟、30–89、90–179、180 分钟以上，无会话则留暗色。

窗口较小时页面可纵向滚动，鼠标位于海报、表格、图表或日历上时，纵向滚轮统一滚动整页；日历和表格的横向滚动条仍可拖动。`Ctrl+F` 聚焦排行搜索。切回游戏库保留未保存设置；统计不在后台高频轮询，进入时首次加载，后续可点击刷新。日期范围和筛选保存在当前窗口内，关闭后恢复默认近 30 天。

## 私人手帐（原型 A）

游戏库详情的“编辑私人手帐…”与档案排行的“归档”按钮打开同一编辑器。每款游戏可标记 **未开始 / 在玩 / 已通关 / 全成就 / 搁置**，未记录默认为未开始；状态完全由用户选择，不根据启动或时长自动推断。

选择已通关或全成就时，尚无通关日期则默认取注入时钟的本地今天，可修改或留空；这两种状态互切保留已有日期，改为其余状态并保存会清除通关日期。私人短评限单行 80 字，点击“保存手帐”才落盘，取消保留原值；保存失败提示并保留编辑内容。两个入口保存后立即更新，无需重载监控或统计。

排行提供“所有状态”及五种状态筛选，与名称 / DataKey 搜索叠加；没有匹配项时提示调整状态、名称或时段。筛选只影响当前时段的排行，不改变总览、日历和节奏汇总；没有该时段历史的游戏可从游戏库详情编辑。

手帐按稳定 `DataKey` 写入配置旁 `config.yml.desktop-journal.json`，沿用 Desktop 侧文档的原子写入与损坏回退。移出游戏库后仍可通过历史排行编辑，改显示名保留原档案。文件缺失或损坏时回退未开始、无日期和空短评。不写 `config.yml`，也不进入自动化链路。现有 sync 只管理聚合报告、每日 CSV 及可选原始 CSV，不同步类型等 Desktop 侧存储，因此手帐同样仅保存在本机。

只落地原型 A；推荐、当日手帐和 SVG 玩家卡片（B/C/D）未纳入。

## 数据口径

界面不显示逐次会话流水，也不请求原始会话页。

历史格式沿用 `playtime.csv`，通过现有快照提供者读取一次，再生成同一份响应中的统计与表格。不会把全部原始历史传到图形界面。

- **按本地结束日期归档**：跨午夜的整条会话归到结束日，与现有历史预览一致。UTC 时间先转换到本地；无时区历史保持原有本地时间含义。
- **沿用保存的分钟数**：不以显示的起止时间重新计算，因此与历史 CSV 合计一致。少于一分钟的会话保留，次数与活跃日期仍增加，分钟数为零。
- **休眠不计入**：监控侧在系统唤醒时把睡眠 / 休眠时长从活跃会话开始时间中剔除，落盘会话的分钟数为纯游玩时间，开始时间即剔除后的有效开始时间。
- **已结束会话**：不叠加当前进行中的计时；未来结束时间、负分钟或结束早于开始的无效记录不计入。
- **历史身份保留**：当前配置中的游戏显示友好名称；已移出的游戏保留历史 DataKey，不会从合计中消失。
- **海报只读复用**：海报直接复用桌面端游戏库已加载的本地缓存与关联，打开统计页不会发起新的 Steam 请求；没有海报或不在当前游戏库的历史条目以首字母占位。
- **跨游戏可重叠**：总时长是各游戏会话分钟数之和，同时运行多款游戏时可能包含重叠，不代表独占屏幕或前台活动时间。

没有记录时显示零值和空态，不生成示例或估计数据。读取失败会保留上一份成功结果并提示重试；快速切换时段只接受最后一次请求，避免旧响应覆盖新页面。

## 实机验证

发布版 `--snapshot` 除游戏库截图外，还输出 `statistics.png`、`statistics-all.png`、`statistics-calendar.png` 和 `statistics-small.png`，覆盖默认时段、全部历史、日历及最小窗口。

`Statistics_PublishedRuntimeRendersDashboardAndSummarizesWithoutChangingHistory` 使用隔离 CSV 和真实 IPC / WPF，验证原始分钟合计、已移出游戏保留、汇总及截图，并检查历史文件字节未变。核心聚合测试使用注入时钟，不依赖机器日期；界面测试覆盖快速切换、游戏和日期汇总、失败重试和关闭时取消。

布局与 A / Studio 对齐：独立标题、全年日历、时间范围工具栏、119px KPI、205px 趋势／最常玩卡、含归档列的排行与 260px 节奏侧卡。最长单次位于最常玩卡底部，最常玩占比以水平进度条展示。年份日历宽度超过窗口时可局部横向滚动，最小窗口仍可访问最近日期；这些展示调整不改变 Core 的已结束会话与分钟数口径。

游玩档案顶部还提供[年度／季度报告](playtime-report.md)：自然期间统计与 Markdown 导出，可选大模型点评。与下方 7 / 30 / 90 天筛选独立。
