# 显示器预设自动切换（monitorMode）

> 适用于 Windows + 支持 DDC/CI 的显示器（HDMI / DP / USB-C 通道均自带该链路），显示器 OSD 里的
> "DDC/CI" 选项需保持开启（默认即开）。首次启用前请先按文末"自测"确认你的显示器档位可被读写。

## 功能概述

GameHelper 监控到游戏启动/退出事件、以及日照窗口变化时，通过 DDC/CI 直接向显示器写入预设档位：

- **白天（日照时间内）且正在游戏** → 游戏预设（如 Dell 的 "Game"）；
- **白天、没有在游戏** → 护眼预设（如 Dell 的 "ComfortView"）；
- **日落到次日日出之间** → 始终护眼预设（即使仍有游戏在跑）。

策略是无状态断言式：每次触发先读回显示器当前档位，与期望不符才写入（手动改过 OSD 也会被下一次触发纠正回来）。触发时机：

1. 游戏进程启动 / 退出（按配置匹配到的游戏）；
2. 监控启动时立即评估一次；
3. 每 10 秒检查日照与显示器可用性；游戏状态、日照、可用性变化或上次写入未确认时重试；
4. 配置热重载后立即重新评估当前游戏与新规则。

写入后会读回全部配方寄存器，只有全部匹配才视为成功。失败时保留重试状态，无需等待下一次游戏事件。
正常无变化时跳过配方读写，可用性探测仍持续运行。停止监控后，已排队的 tick 不会继续切换档位。

连接状态提示只在状态变化时输出：启动时报告初始状态，断开时警告一次，恢复时提示一次。
显示器持续在线时，每 10 秒的正常探测不会重复打印 `monitor became available`；这类重复提示是日志状态判断问题，不代表显示器反复重连。

默认关闭，需在 `config.yml` 中显式打开。

## 配置

最少配置（其余字段使用默认值）：

```yaml
monitorMode:
  enabled: true
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 总开关 |
| `location` | string | `off` | 坐标来源："auto" 开启自动定位（见下文"自动获取位置"）；无坐标时仍用固定时间窗 |
| `latitude` | double | null | 纬度（十进制度，北正），与 `longitude` 必须同时出现；**手动值优先级最高** |
| `longitude` | double | null | 经度（东正）。两者都配置后按 NOAA 算法逐日计算日出日落 |
| `daylightStart` | "HH:mm" | `"07:00"` | 手动坐标与自动定位都不可用时的固定日照开始时间（含端点） |
| `daylightEnd` | "HH:mm" | `"18:30"` | 固定日照结束时间（不含端点，跨零点窗口如 `21:00`→`07:00` 也支持） |
| `gamePresets` | 列表 | U2720QM 游戏配方 | 游戏时要依次写入的 DDC/CI 码对，顺序敏感 |
| `comfortPresets` | 列表 | U2720QM 护眼配方 | 非游戏/日落后要依次写入的码对，顺序敏感 |

- 码对写法：`code` 恒为十六进制（`"DC"` 或 `"0xDC"`）；`value` 有 `0x` 前缀按十六进制，否则按十进制。
- 极昼按全天日照、极夜按全天黑夜处理。
- 坐标只影响"白天"判定，其余行为不变;配置热重载生效（约 0.5 秒）。

## 预设配方（默认针对 Dell U2720QM 实测定标）

以下配方是在 U2720QM 上用"显示器 OSD 手动切档 + 只读 DDC 监听"逐项定标得出的，且已通过
真实写入验证（写入后寄存器状态与显示器原生切档完全一致）：

| 模式 | 依次写入 |
| --- | --- |
| 游戏模式 | `DC=0x05` → `E2=0x04` → `F0=0x00` |
| 护眼模式 | `DC=0x00` → `E2=0x1D` → `F0=0x0C` |

要点：

- **必须整组顺序写入且以 `F0` 收尾**。实测只写 `E2`（护眼档位码）会被显示器在数秒内回退为
  标准档（`E2=0x00`）；`F0` 是护眼档案的联动开关，缺了它整组写入无效。
- 换显示器时把两组 `gamePresets`/`comfortPresets` 覆盖为你的显示器配方即可。定标方法见文末"自测"。
- 配方写入顺序在模型里保留（列表即写入顺序），控制器不会重排。

## 与 HDR 自动化的关系

游戏条目的 `hdr: true` 仍按原逻辑工作。HDR 打开期间显示器被系统接入 HDR 模式，DDC 预设写入可能
无法改变画面表现（这属于显示器固件行为）；HDR 关闭后下一次触发会重新对齐预设档位。两者互不干涉配置。

## 注意事项

- **只有一个实例可启用该功能**：DDC/CI 是整机唯一的总线通道，两个同时启用 `monitorMode` 的
  GameHelper 实例会互相抢写。验证流程使用沙箱实例时，请仅在其中一个启用。
- **显示器"离线"状态的功能表现**：显示器关机、切换到其他输入源或深度休眠时，系统层面拿不到
  物理监视器（`WmiMonitorID` 清空、`GetPhysicalMonitorsFromHMONITOR` 失败），控制器进入待命状态并
  每 10 秒自愈重试；显示器回到 PC 输入源后 ≤10 秒自动恢复工作并按规则对齐档位，无需重启。
  另：.NET 8 下 dxva2 的结构体数组封送存在回读丢句柄的缺陷，控制器已改用原始缓冲区读写规避。
- 显示器休眠/关屏期间的写入会失败并记录日志，唤醒后下一次 10 秒检查会自动补齐；硬件总线调用耗时另计。
- OSD 中误关 "DDC/CI" 会导致读取全部失败，控制器判定不可用并跳过自动化（日志有提示）。
- 该功能只写预设档位，不修改亮度/对比度等数值。

## 自测与定标方法

1. 只读确认显示器 DDC/CI 可用：启用 `monitorMode` 后看 GameHelper 日志
   `DDC/CI monitor preset automation controller ready (Dell U2720QM ...)`。未出现说明通道不可用。
2. 先手动把 OSD 切到游戏模式，观察日志 `Switching monitor preset to ...` 是否与你配置的期望一致；
   再把 OSD 上下切一档确认自动纠正生效。
3. 需要为新显示器定标配方时：用 OSD 在"目标档位 ↔ 任意其他档位"间切换，同时用
   `dxva2` 的 `GetVCPFeatureAndVCPFeatureReply`（或 ddcutil/ControlMyMonitor）只读监听全部 VCP 码，
   变化的码对即为该档位配方；按本指南字段格式填入 `config.yml` 并覆盖默认值。

## 发布产物与真实硬件回归

先把其他运行实例的 `monitorMode.enabled` 临时设为 `false`，确认热重载完成，避免抢写。
设置 `GAMEHELPER_TEST_PUBLISH_EXE` 指向新发布 exe，设置 `GAMEHELPER_TEST_DDC=1` 后运行：

```powershell
dotnet test GameHelper.sln --filter FullyQualifiedName~MonitorMode_WhenHardwareVerificationEnabled --logger 'console;verbosity=normal'
```

测试使用独立数据目录、真实 ETW 进程和 DDC 控制器，验证启动护眼、游戏启动游戏模式、
热重载夜间规则护眼、重载日间规则游戏模式、退出游戏护眼。每步读回 `DC/E2/F0`，再等 3 秒确认固件未回退。
结束后清除测试环境变量并恢复主实例开关。普通测试不设置该变量，不会写真实显示器。
