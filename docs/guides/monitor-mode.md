# 显示器预设自动切换（monitorMode）

> 适用于 Windows + 支持 DDC/CI 的显示器（HDMI / DP / USB-C 通道均自带该链路），显示器 OSD 里的
> "DDC/CI" 选项需保持开启（默认即开）。首次启用前请先按文末"自测"确认你的显示器档位可被读写。

## 功能概述

GameHelper 监控到游戏启动/退出事件、以及日照窗口变化时，通过 DDC/CI 直接向显示器写入预设档位：

- **未绑定设备** → 不执行预设；配方必须明确归属具体显示设备；
- **绑定设备已开启 HDR、离线或身份无法确认** → 只暂停该设备，不探测或读写它的 DDC；其他绑定的 SDR 显示器继续按自己的配方运行；
- **白天（日照时间内）且正在游戏** → 游戏预设（如 Dell 的 "Game"）；
- **白天、没有在游戏** → 护眼预设（如 Dell 的 "ComfortView"）；
- **日落到次日日出之间** → 始终护眼预设（即使仍有游戏在跑）。

策略是无状态断言式：每次触发先读回显示器当前档位，与期望不符才写入（手动改过 OSD 也会被下一次触发纠正回来）。触发时机：

1. 游戏进程启动 / 退出（按配置匹配到的游戏）；
2. 监控启动时立即评估一次；
3. 每 10 秒查询当前 HDR 状态；确认 HDR 已关闭时再检查日照与显示器可用性。游戏状态、日照、可用性变化或上次写入未确认时重试；
4. 配置热重载后立即重新评估当前游戏与新规则。

写入后会读回全部配方寄存器，只有全部匹配才视为成功。失败时保留重试状态，无需等待下一次游戏事件。
SDR 下正常无变化时跳过配方读写，可用性探测仍持续运行。停止监控后，已排队的 tick 不会继续切换档位。

连接状态提示只在状态变化时输出：启动时报告初始状态，断开时警告一次，恢复时提示一次。
显示器持续在线时，每 10 秒的正常探测不会重复打印 `monitor became available`；这类重复提示是日志状态判断问题，不代表显示器反复重连。

默认关闭，需显式开启并绑定设备；只打开总开关不会自动选中当前主屏幕或电视。

## 配置

推荐在游戏库“全局设置 → 按设备配置预设”中选择实际显示器，再绑定旧配方或为这台设备录制。选择框默认空白，需要明确选择；每台设备有独立开关、配方、连接状态与解除绑定入口。保存后热重载生效，未连接设备的配置保留。

配置示意（设备路径与硬件身份由选择实际设备生成，不要照抄占位值）：

```yaml
monitorMode:
  enabled: true
  daylightStart: "07:00"
  daylightEnd: "18:30"
  displays:
    - device:
        name: DELL U2720QM
        devicePath: '实际 Windows 显示设备路径'
        hardwareKey: '从该设备 EDID 读取的型号与序列号身份'
      enabled: true
      gamePresets:
        - { code: DC, value: '0x05' }
        - { code: E2, value: '0x04' }
        - { code: F0, value: '0x00' }
      comfortPresets:
        - { code: F0, value: '0x0C' }
```

名称只用于展示，不参与匹配；主屏幕编号、枚举顺序和“第一台可控制显示器”都不是绑定依据。有可靠 EDID 序列号时，使用厂商、产品与序列号识别，换接口后仍可匹配；没有可靠序列号时，仅精确匹配已保存设备路径，路径变化必须重新绑定。身份重复、克隆显示模式或无法唯一关联物理句柄时跳过，绝不回退到另一台显示器。每次操作重新取得句柄，写入前再次确认连接和该设备的 HDR 状态。

旧配置的顶层 `gamePresets` / `comfortPresets` 保留为待绑定模板，不再作为通用预设执行。`displays` 缺省或空列表时不自动写入任何设备，也不会把升级时恰好连接的电视绑定成旧配方目标。接回原显示器后可在界面明确绑定，原日照与位置设置保留。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 总开关 |
| `location` | string | `off` | 坐标来源："auto" 开启自动定位（见下文"自动获取位置"）；无坐标时仍用固定时间窗 |
| `latitude` | double | null | 纬度（十进制度，北正），与 `longitude` 必须同时出现；**手动值优先级最高** |
| `longitude` | double | null | 经度（东正）。两者都配置后按 NOAA 算法逐日计算日出日落 |
| `daylightStart` | "HH:mm" | `"07:00"` | 手动坐标与自动定位都不可用时的固定日照开始时间（含端点） |
| `daylightEnd` | "HH:mm" | `"18:30"` | 固定日照结束时间（不含端点，跨零点窗口如 `21:00`→`07:00` 也支持） |
| `displays` | 列表 | 空 | 显式绑定的设备与各自配方；空列表不执行自动写入 |
| `displays[].gamePresets` | 列表 | 无，必须配置 | 只写入对应设备的游戏配方，顺序敏感 |
| `displays[].comfortPresets` | 列表 | 无，必须配置 | 只写入对应设备的舒适配方，顺序敏感 |

- 码对写法：`code` 恒为十六进制（`"DC"` 或 `"0xDC"`）；`value` 有 `0x` 前缀按十六进制，否则按十进制。
- 极昼按全天日照、极夜按全天黑夜处理。
- 坐标只影响"白天"判定，其余行为不变;配置热重载生效（约 0.5 秒）。

## 预设配方（默认针对 Dell U2720QM 实测定标）

以下配方是在 U2720QM 上用"显示器 OSD 手动切档 + 只读 DDC 监听"逐项定标得出的，且已通过
真实写入验证（写入后寄存器状态与显示器原生切档完全一致）：

| 模式 | 依次写入 |
| --- | --- |
| 游戏模式 | `DC=0x05` → `E2=0x04` → `F0=0x00` |
| 护眼模式 | 单笔 `F0=0x0C`；固件联动设置 `DC=0x00`、`E2=0x1D` |

要点：

- **U2720QM 可用一笔 `F0=0x0C` 直接进入护眼**：2026-10-20 从完整游戏状态实测，读回 `DC=00 / E2=1D / F0=0C`，等待 3.5 秒后保持。旧三笔护眼配方仍可自定义，但默认不再先写 `DC=00`。只写 `E2` 会回退，不能据此推断必须写三笔。
- DDC/CI 每次 `SetVCPFeature` 只写一个 VCP 码，没有多码原子提交。固件是否联动、能否缩短间隔须按型号实测：本机三笔间隔 20ms 可保持，零间隔三笔却回退成 `E2=00 / F0=00`。自定义多笔配方仍保留 400ms 间隔，不能把这个失败结论推广到所有显示器。
- 寄存器保持不等于已确认没有任何画面过渡；单笔配方避免了程序先显式写标准档的步骤，实际视觉效果仍以屏幕表现为准。
- 新增显示器时，为这台设备单独绑定并录制两组配方；不能把 Dell 厂商码当作其他显示器的通用配方。定标方法见文末"自测"。
- 配方写入顺序在模型里保留（列表即写入顺序），控制器不会重排。

## 与 HDR 自动化的关系

游戏条目的 `hdr: true` 结合全局 `hdr.allowedDisplays` / `hdr.disabledDisplays` 选择自动 HDR 的目标，详见[游戏库 HDR 策略](game-library.md#hdr-和启动失败)。HDR 权限与 DDC 预设绑定相互独立：允许电视 HDR 不会允许在电视上执行 Dell 预设。

预设评估按绑定设备自己的 HDR 状态执行。目标设备 HDR 开启时暂停它的预设；状态查询失败、目标离线或身份不唯一时也跳过。目标确认恢复 SDR 后重新评估，无需等待新的游戏事件。电视处于 HDR 不会阻止另一台绑定的 SDR 显示器切换预设；库内/外部启动都按实际目标状态和日照规则处理。

仅在预设状态变化时记录暂停/恢复原因；未知设备不写、未绑定旧配方不写、两份配方解析到同一设备时也不写。测试实例仍必须隔离数据并保持自动预设关闭，真实硬件写验证需单独显式选择目标。

## 注意事项

- **只有一个实例可启用该功能**：DDC/CI 是整机唯一的总线通道，两个同时启用 `monitorMode` 的
  GameHelper 实例会互相抢写。验证流程使用沙箱实例时，请仅在其中一个启用。
- **显示器"离线"状态的功能表现**：显示器关机、切换到其他输入源或深度休眠时，系统层面拿不到
  物理监视器（`WmiMonitorID` 清空、`GetPhysicalMonitorsFromHMONITOR` 失败），控制器进入待命状态并
  每 10 秒自愈重试；显示器回到 PC 输入源后 ≤10 秒自动恢复工作并按规则对齐档位，无需重启。
  另：.NET 8 下 dxva2 的结构体数组封送存在回读丢句柄的缺陷，控制器已改用原始缓冲区读写规避。
- 显示器休眠/关屏期间的写入会失败并记录日志，唤醒后下一次 10 秒检查会自动补齐；硬件总线调用耗时另计。
- OSD 中误关 "DDC/CI" 会导致读取全部失败，控制器判定不可用并跳过自动化（日志有提示）。
- 该功能只写预设档位，不修改亮度/对比度等数值。

## DDC 两步录制向导

WPF“全局设置 → 显示器预设 → 录制游戏 / 舒适预设”提供只读录制：

1. 先关闭自动预设并保存，在全局设置明确选择要配置的显示设备；关闭该设备 HDR，确认它在线且 DDC/CI 已开启。使用这台显示器的实体菜单切到舒适模式，读取第一个快照。
2. 保持连接不变，切到游戏模式并读取第二个快照。预览两个方向的变化码，点击“使用这两份配方”，回到设置页保存；需要时再启用自动切换。

默认候选码依次为 `0xDC, 0xE2, 0xF0, 0x14`。单码读取失败会跳过，只有前后都读成功且数值变化的码进入配方；数值不在现有配方支持的 0–255 范围内时跳过。没有变化会提示重新读取，不生成空配方。显示器连接变化、HDR 开启／状态未知或离线时拒绝该次快照，不能混合两次不同连接的快照。

录制期间不调用 DDC 写入；两次快照都限定到明确选定的同一设备。厂商专有码和写入顺序可能需要人工定标；默认候选没有变化时可沿用下面的手工定标方法。录制出的配方只替换该设备自己的游戏／舒适配方，其他设备、位置与日照配置保留。

## 自测与定标方法

1. 只读确认显示器 DDC/CI 可用：启用 `monitorMode` 后看 GameHelper 日志
   `DDC/CI monitor became available`（并核对绑定设备名称）。未出现说明通道不可用。
2. 先手动把 OSD 切到游戏模式，观察日志 `Switching monitor preset to ...` 是否与你配置的期望一致；
   再把 OSD 上下切一档确认自动纠正生效。
3. 需要为新显示器定标配方时：用 OSD 在"目标档位 ↔ 任意其他档位"间切换，同时用
   `dxva2` 的 `GetVCPFeatureAndVCPFeatureReply`（或 ddcutil/ControlMyMonitor）只读监听全部 VCP 码，
   变化的码对即为该档位配方；按本指南字段格式填入 `config.yml` 并覆盖默认值。

## 发布产物与真实硬件回归

这项写入回归要求 Windows HDR 已关闭且状态可查询，测试不会自动切换 HDR；HDR 开启时应跳过实机写入验证，使用 HDR 阻断的单元回归与只读系统查询。先把其他运行实例的 `monitorMode.enabled` 临时设为 `false`，确认热重载完成，避免抢写。
设置 `GAMEHELPER_TEST_PUBLISH_EXE` 指向新发布 exe，设置 `GAMEHELPER_TEST_DDC=1`，并将 `GAMEHELPER_TEST_DDC_DEVICE_PATH` 设为明确选择的 U2720QM 设备路径后运行（该回归使用 Dell 专用配方，拒绝其他型号或缺少显式目标）：

```powershell
dotnet test GameHelper.sln --filter FullyQualifiedName~MonitorMode_WhenHardwareVerificationEnabled --logger 'console;verbosity=normal'
```

测试使用独立数据目录、真实 ETW 进程和 DDC 控制器，验证启动护眼、游戏启动游戏模式、
热重载夜间规则护眼、重载日间规则游戏模式、退出游戏护眼。每步读回 `DC/E2/F0`，再等 3 秒确认固件未回退。
结束后清除测试环境变量并恢复主实例开关。普通测试不设置该变量，不会写真实显示器。

设备映射依据：[Microsoft DISPLAYCONFIG_SOURCE_DEVICE_NAME](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_source_device_name)、[Microsoft PowerToys 显示控制设计](https://github.com/microsoft/PowerToys/blob/main/doc/devdocs/modules/powerdisplay/design.md)。
