# SQLite 维护、恢复和安全退回旧版本

历史、在途会话及已导入的六类 Desktop 文档以数据目录中的 `userdata.db` 为权威。
默认目录为 `%AppData%\GameHelper`；`GAMEHELPER_DATA_DIR` 指定 base directory，仍追加 `GameHelper`。
所有维护命令使用相同的数据目录与 `--config`。不要把正在运行的 `.db` 单独复制或覆盖，WAL/SHM 也属于现场。

## 自动维护与提示

后台启动后、之后每分钟在自动化状态锁外维护。跨进程目录锁选择一个执行者；维护准入独占文件租约，
已有业务写入时直接跳过，业务写入等待维护也计入原事件的五秒争用预算，超时保留固定终点待补录。
备份使用 `BackupDatabase`，可能阻挡写入；完整备份和磁盘 I/O 不承诺五秒完成。

每日第一次维护运行 `integrity_check` 和 `foreign_key_check`；成功 UTC 日期记录在库内。
每次维护做 PASSIVE checkpoint，不等待长读事务，下次维护在读者释放后推进。
按注入时钟的 UTC 日期，每日第一次发现用户数据修订变化后创建完整、校验过的本机备份；
无变更不备份，同日最多一个成功版本，失败下分钟重试、不删除上一成功版本。
`backups/daily-*` 保留最近 7 个成功版本，`upgrade-*` 保留最近 3 个升级前版本；迁移原件包单独永久保留。
每份 manifest 包括数据库 ID、schema、历史／用户修订、时间、耗时、摘要。

托盘与运行日志提示投影、备份和完整性故障，分别恢复后清除。
投影失败不回滚库中数据，只表示暂不能让旧版接手；每次维护重试，正常停止仍排空。
完整性／外键失败会留下 `.userdata.unhealthy`，所有新连接拒绝写入和同步读取；
不要删除标记来绕过检查，也不自动改写损坏现场或回落到 CSV。

备份含私人文本和草稿，仅落本机，不进入 sync。完整用户环境还需另外保留 YAML 和配置绝对路径／scope 清单；
图片与定位缓存可以重建。备份只保证备份时刻的数据，之后的增量需与保留现场和兼容投影人工核对。

## 显式恢复

1. 关闭全部后台与游戏库，保留当前目录（尤其 DB/WAL/SHM）。
2. 用新版运行 `GameHelper.ConsoleHost.exe storage restore "<backups/daily-...目录>" --config "<配置路径>"`。
3. 工具先核对 SHA-256、schema、metadata、完整性与外键，在独立候选库恢复并验证后整体换入；损坏备份拒绝换入。
   原 DB/WAL/SHM 保留在 `recovery-originals/`，恢复成功清除故障标记。
4. 启动新版；数据库 ID 已更换，旧 sync 书签必定失效，按原内容指纹策略重新判断是否上传。

全部连接均不使用连接池；恢复时仍必须停止全部进程，目录锁不等于停止业务 writer。

## 首个正式版的兼容窗口

首个 SQLite 正式发布版本保留一个完整发布周期的实时旧格式投影，包括 CSV、在途 JSON 及已导入 scope 的六种 JSON。
CSV/JSON 是兼容输出，不能手工修改后直接覆盖新版数据库。

安全退回旧版本：

1. 停止所有 ConsoleHost 与 Desktop，保留新版可执行文件。
2. 执行 `GameHelper.ConsoleHost.exe storage prepare-downgrade --config "<配置路径>"`。
   新版排空投影，以固定修订核对旧读取器统计、全部投影字节／哈希，封存数据库和旧文件，输出 `downgrade-backups/<id>/manifest.json`。
3. 执行 `storage check-downgrade --config "<配置路径>"` 作离线预检；任何失败都应停止降级。
   预检只验证、不修复；重新执行准备降级会重试投影并产生新的完整封存包。
4. 保存 manifest 路径，再启动旧版。正在运行的游戏通过导出的旧快照接管。UUID、启动来源及评分等旧格式不能表示的数据保留在封存库。
5. 再升级前，先停止旧版两进程，使用新版 `storage reupgrade "<manifest路径>" --config "<配置路径>"`，成功后才启动新版。
   旧版追加记录按完整有序前缀及重复 occurrence 合并一次，原 session_id 保持；侧文档导入旧版最新值。
   旧版删除、改写、重排历史时停止自动合并，保留两边原件供人工核对。

手工覆盖安装且没有 manifest 不承诺安全降级。首次成功启动不会删除旧备份。
下一正式版本关闭实时投影前，必须另行验收离线准备降级、再升级、在途接管、不可表达字段封存、故障阻断及恢复测试；
版本说明须明确窗口已结束、旧文件可能过期和正确的离线命令。本批继续实时投影，离线工具长期保留。
